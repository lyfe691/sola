# Free films and series, and a place to watch them together

[Kinoa](https://kinoa.to) is a free site for watching films and series, with a social side built around the player: profiles, a feed, comments, messages and rooms for watching together. Around 10,000 people use it each month, and about a thousand of them have an account.

It started in November 2025 as a search box and a player. Everything below was added since, one release at a time.

## Finding something to watch

Everything starts from one search box. Results arrive while you type, each with its poster, year and rating, the rest of the most likely title is completed in grey, and the arrow keys move through the list. Below the search, the home page shows what you were watching and what everyone else is watching this week.

Every card opens in place when you hover it: the poster widens into the title's artwork, with the synopsis and a button to start watching.

## Playing it

Films and series play in players embedded from other sites, and not every one of them has every title. The row under the player names the current server and tags each with what it's good at, such as best quality or most reliable. When the default doesn't load, a hint offers the next one in a tap. On a phone, playback can switch straight into the device's own fullscreen player.

A series gets an episode picker by season, with the episode you're on highlighted.

## Watching together

A room is a link. The host picks a title and shares the room, and everyone who joins watches the same moment, with a chat beside the player. When the host pauses, skips ahead or switches episode, the room follows. Hosts can hand hosting to someone else, remove people and ban them, and each room can be listed in the public directory or kept to the people who have the link.

## Profiles, the feed and messages

Every account gets a handle and a public page at kinoa.to/@name, with favorites, a watchlist and what was watched recently. One switch makes the whole profile private. People follow each other, like titles and comment on them, and the feed shows comments, favorites and follows from everyone on Kinoa, newest first.

Direct messages have reactions, editing and deleting, and blocking and reporting. A notification bell collects replies, mentions, likes and follows as they happen, and says when a title you follow comes out.

## Design and motion

Kinoa uses a warm palette of cream and espresso with a caramel accent, in a light and a dark theme that follow the system unless you pick one. It moves in small ways that confirm what happened. Pages stream in and reveal each part where its placeholder stood, the sidebar glides open and closed, a rejected form shakes the field that's wrong, and dialogs change size smoothly instead of jumping. All of it steps back for visitors who ask their system for reduced motion. Kinoa also installs as an app, from the browser on a computer or Android, or with a short guide on an iPhone.

## How it's built

Kinoa is a Next.js app, mostly server components, on Supabase for accounts, the database and the realtime channels that rooms run on. It's deployed on Vercel and translated with next-intl.

### Keeping a room on one clock

The embedded players are the hard constraint: they can't be told to pause or jump to a time. So a guest who drifts away from the host reloads their player at the host's position, projected forward by how long a reload takes. Each reload measures where it actually landed and corrects the next one, and it aims a fraction of a second behind the host, since being early spoils a scene and being late doesn't.

<CodeBlock
  code={`/** Aim a touch behind the host — being early spoils, being late doesn't. */
  export const TARGET_DRIFT_SECONDS = -0.75
  /** Share of each landing error folded into the next lead estimate. */
  export const LEAD_LEARNING_RATE = 0.6
  export function anchorTargetFor(
    host: HostAnchor,
    now: number,
    leadSeconds: number
  ): AnchorTarget {
    if (!host.isPlaying) {
      return { time: Math.max(0, host.currentTime), play: false }
    }
    return {
      time: Math.max(0, projectPlayhead(host, host.at, now) + leadSeconds),
      play: true,
    }
  }
  export function nextLoadLead(lead: number, driftAtSettle: number): number {
    const error = driftAtSettle - TARGET_DRIFT_SECONDS
    const next = lead - error * LEAD_LEARNING_RATE
    return Math.min(
      MAX_LOAD_LEAD_SECONDS,
      Math.max(MIN_LOAD_LEAD_SECONDS, Number.isFinite(next) ? next : lead)
    )
  }`}
  fileName="lib/watch-together-playhead-sync.ts"
  lang="ts"
/>

Reloads cost a buffer, so a guest only reloads after drifting several seconds for two checks in a row, and after a few tries it hands the decision to a Catch up button.

### Rules the database enforces

Only the host can steer a room. That rule is a row-level security policy on the room's control channel rather than a check in the app, so it holds for any client, and an integration test signs in as a guest, sends every control command and checks that the host receives none of them. Handles work the same way: they're claimed through one database function that owns every rule, from length and reserved names to moderation, and a unique index settles two people claiming the same name at once.

### Fewer round trips

Checking who is signed in goes over the network to Supabase Auth, and a movie page used to do it three times in one render, the feed page four. The session helpers now share one cached result per render, so it happens once. A watchlist row now carries the title, poster and backdrop it's drawn with, so a long list renders from one query instead of fetching every title from TMDB. And the version check every open tab makes every five minutes is answered from Vercel's edge cache instead of running a function each time.

### Keeping the translations complete

English is the source for every string. A check in CI compares every other language file against it and fails when a key is missing or left over, so a new feature can't ship half translated.
