# A TCP and UDP port scanner in Rust

magi is a command-line port scanner I wrote in Rust. It does connect scanning: every probe is an ordinary TCP connection or UDP datagram made through the operating system's sockets, so it runs as a normal user on Linux, macOS and Windows. It reports a port only in a state it actually observed, and says so when it couldn't test one.

## Scanning a host

You give magi a target and it probes the ports you ask for, 1 to 1024 unless you say otherwise. The target can be a hostname, an IP address or a whole subnet in CIDR notation, and ports can be single numbers, ranges or a mix. Open ports are listed under their host with the usual service name, and `--banner` adds the first line each service sends back, such as an SSH server's version. While a longer scan runs, a counter shows how many ports have been probed and how many are open.

The run above is against 45.33.32.156, scanme.nmap.org, a host the Nmap project keeps up for testing scanners, and it took about a second. Flags set how many probes run at once (512 by default), how long each one waits for an answer, and an optional cap on how many start per second. A subnet larger than a /16 is refused, so a mistyped prefix can't turn into millions of probes.

<CodeBlock
  code={`magi 192.168.1.0/24 --ports 22,80,443      # a whole subnet, grouped by host
  magi 10.0.0.5 --ports 1-65535 -c 1024      # every port, 1024 probes in flight
  magi 192.168.1.1 --ports 53,123,161 --udp  # UDP instead of TCP
  magi scanme.nmap.org -p 22,80 --json | jq  # JSON on stdout, progress on stderr`}
  fileName="examples.sh"
  lang="bash"
/>

## Output for scripts

Everything meant for a person goes to stderr: the line that opens the scan, the counter and any warning. The counter only appears when stderr is a terminal. With `--json`, stdout carries a JSON array of the open ports with their address, protocol, state and banner, so the results pipe straight into jq or another program.

## UDP

`--udp` probes UDP instead. UDP has no handshake, so magi reads the verdict from how the host reacts to an empty datagram: a reply means open, an ICMP port-unreachable means closed, and silence until the timeout means `open|filtered`. An open service that ignores an empty datagram and a firewall that drops it look the same from outside, and magi says so instead of picking one. In this run 53 and 161 came back closed and are left out, while 123 stayed silent for the whole second.

## Ports it couldn't test

When a probe can't run at all, magi doesn't count the port as closed. It counts it as untested and ends the scan with a warning that says how many there were and why. scanme.nmap.org has an IPv4 and an IPv6 address, and magi scans every address a name resolves to. On a network without IPv6 routing, the connections to the IPv6 address fail with "network unreachable" before anything is sent, so the three ports there are reported as untested. When the cause is running out of file descriptors, the warning says to lower `--concurrency` or raise the open-file limit.

## How it's built

magi is a small library under a thin binary. `main.rs` parses the arguments, expands the target and prints the results, and `scanner.rs` holds the scan itself, banner grabbing, UDP and the service names. It runs on tokio, with clap for the flags and serde for the JSON. GitHub Actions runs rustfmt, clippy and the tests on every push, and cargo-dist builds the release archives and the install scripts. The site is Next.js, translated with next-intl.

### A fixed number of probes in flight

A /24 across ports 1 to 1024 is about 260,000 probes, and spawning a task for each up front would hold all of them in memory at once. The scan loop takes a semaphore permit before it spawns each probe instead, so once `--concurrency` probes are in flight it waits for one to finish. The permit moves into the task and is released when the probe ends, and the loop collects finished probes as it goes, so the number of live tasks stays bounded however large the scan is. Abridged from `scan()`:

<CodeBlock
  code={`let permits = config.concurrency.clamp(1, MAX_CONCURRENCY);
  let limiter = Arc::new(Semaphore::new(permits));
  let mut tasks = JoinSet::new();
  let mut summary = ScanSummary::default();
  for &target in targets {
      for &port in ports {
          let permit = Arc::clone(&limiter)
              .acquire_owned()
              .await
              .expect("semaphore stays open for the duration of the scan");
          tasks.spawn(async move {
              let _permit = permit;
              probe(target, port, timeout_dur, grab_banner, protocol).await
          });
          while let Some(joined) = tasks.try_join_next() {
              collect(&mut summary, &mut progress, joined);
          }
      }
  }`}
  fileName="src/scanner.rs"
  lang="rust"
/>

The optional rate cap is a tokio interval ticked before each spawn. The semaphore limits how many probes run at once and the interval limits how many start per second, and missed ticks are delayed, so a slow stretch never releases a burst of probes to catch up.

### Telling closed from untested

A TCP connect settles the question in two cases: it completes and the port is open, or the host refuses it and the port is closed. A connect that times out also counts as not open, since no reply came back. Every other error says nothing about the port, and it's sorted into one of two untested kinds:

<CodeBlock
  code={`fn classify_connect_error(e: &io::Error) -> ProbeOutcome {
      match e.kind() {
          ErrorKind::ConnectionRefused | ErrorKind::TimedOut => ProbeOutcome::NotOpen,
          _ if is_fd_exhaustion(e) => ProbeOutcome::Untestable(Untestable::OutOfDescriptors),
          _ => ProbeOutcome::Untestable(Untestable::Other),
      }
  }`}
  fileName="src/scanner.rs"
  lang="rust"
/>

Because the scanner is a library, the integration tests call the real `scan()` against sockets on loopback. One of them lowers the process's open-file limit to 128, scans 400 local ports with 300 probes in flight over TCP and then UDP, and checks that both results count untested ports and name the descriptor limit as the cause.

### UDP without raw sockets

Seeing an ICMP port-unreachable normally takes a raw socket, and with it root. magi connects its UDP socket to the target before sending, which filters replies to that one peer and makes the operating system report the ICMP message as a `ConnectionRefused` error on the next receive. The closed verdict then depends on the OS passing those errors back, which Linux does reliably. macOS and Windows rate-limit ICMP, so on them some closed ports read as `open|filtered`.

### Banners from untrusted hosts

With `--banner`, magi reads up to 512 bytes from each open port and keeps the first line. That text comes from a host you don't control and ends up in your terminal, so every control character is removed before it's printed. A raw escape sequence in a banner could otherwise clear the screen, retitle the window or overwrite earlier output, and a unit test passes an ANSI clear-screen sequence through to check that only printable text comes out.
