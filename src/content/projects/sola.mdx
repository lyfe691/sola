# The portfolio you're reading

Sola is my portfolio, the site you're on at [sola.ysz.life](https://sola.ysz.life). It holds my projects, the tools I work with, where I've worked and a way to reach me, and I've been building it since February 2025. Most of my time on it goes into how its pages look and move.

## The home page

The home page is a greeting and a way onward. The name in it cycles through the ones I go by, Yanis, Sebi and lyfe691, and pressing it skips to the next. The line under it cycles too, each sentence spelled out letter by letter from a blur. Above the greeting, a small link points to what I'm working on now.

The two buttons are glass, edged with a soft rim of light and a glint that sweeps around them and turns toward the pointer. The social links below open into their name and brand colour on hover. Moving to another page blurs the current one away, and the next one comes into focus from the same blur. On a first visit, a note by the menu says which theme and background I picked and where to change them.

## Themes and backgrounds

The menu at the top right changes how the whole site looks. Next to light, dark and following the system, there are custom themes with palettes of their own, and hovering one shows a small preview before you pick it. A new theme dissolves in over the old one in under half a second, and the menu stays open, so the next one is a click away.

Behind every page can run an animated background, a WebGL scene that takes its colours from the theme, picked from the same menu. Some are soft gradients, others move like silk or watercolour, and one is a fluid that follows the pointer.

## Projects

The projects page is a grid of cards. Each has a cover in the project's own colours, its dates set into a notch at the corner, a short description and the technologies it uses. A filter separates personal projects from work for clients, and a menu sorts them as featured, newest, oldest or by name.

When the order changes, every card on screen crossfades with a short blur into the one that takes its place, so the grid keeps its shape while its contents change.

## The changelog

The changelog is this site's git history, read from GitHub. Each commit shows its kind and the part of the site it touched, marks for the file types it changed and a bar of lines added and removed, along a rail that shows where branches merged back in. The commit the live site was built from is labelled. Opening one shows its full message, a tree of the files it changed and the diff of each.

## Getting around

⌘K, or Ctrl+K, opens a palette for moving around from the keyboard: it goes to any page, switches the theme, language or background, and turns on the git diff. The whole site is translated, and it opens in the language the browser asks for. An address that doesn't exist lands in a small terminal, which answers with git's error for a missing path and a hint for the way home.

## How it's built

Sola is a React app in TypeScript, built with Vite, styled with Tailwind CSS and shadcn/ui components, and animated with Motion. The backgrounds are drawn with three.js and OGL. It's deployed on Vercel, where serverless functions fetch the GitHub activity and the changelog's commits.

### Content counts as painted when it starts to appear

Every entrance on the site is a fade, and each one used to start from opacity 0. Chrome's Largest Contentful Paint (LCP), the moment the largest piece of content on screen counts as drawn, skips anything painted at opacity 0, and a fade runs on the compositor without painting again. So a block counted only once its fade had finished, and every page's LCP carried a 0.7-second glide. In a Chrome trace with the CPU slowed four times, the contact page's subtitle started its reveal at 941 ms and counted at 1536 ms.

Entrances now start at 0.001, which is less than one step of an 8-bit colour channel even on white. Nothing looks different, but the browser counts the paint as soon as the fade begins. In the same trace, the projects page counted at 1136 ms instead of 2764 ms and the home page at 1120 ms instead of 2032 ms.

### One list of routes

Every page is one entry in `src/config/routes.ts`: its path, the code to load, the layout and the tab title.

<CodeBlock
  code={`{
    path: "/projects",
    layout: "app",
    ...page(() => import("@/pages/Projects")),
    title: (t) => t.projects.title,
  },`}
  fileName="src/config/routes.ts"
  lang="ts"
/>

The router renders from that list, and so does a build step that writes a small script into `index.html`. The script matches the address against the same list and starts downloading that page's code while the main bundle is still arriving, where before the page's code was requested only after the whole bundle had downloaded and run. The build fails if an entry's path and page stop pairing up, so the list and the script can't drift apart.

### One language per visitor

Every translation used to ship in the startup bundle, 156 KB minified, although a visitor reads one. English is still bundled as the fallback, and every other language is its own chunk of about 11 KB compressed, fetched before the first render alongside the page's code, so a German visit waits no longer than an English one. Switching language keeps the current words on screen until the new ones have loaded.
