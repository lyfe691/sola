# Ein QR-Code-Generator mit Scan-Test

[qr.ysz.life](https://qr.ysz.life) erzeugt QR-Codes im Browser. Sie tippen einen Link oder einen beliebigen Text ein, gestalten den Code und laden ihn herunter. Das Gestalten kann aber auch dafür sorgen, dass sich ein Code nicht mehr scannen lässt, deshalb sitzt in der Kopfzeile ein Scan-Test, der ein exportiertes Bild mit einem echten Decoder wieder einliest.

## Formen und Punktstile

Der Reiter Style bestimmt, wie der Code gezeichnet wird. Seine Module, die kleinen Quadrate, aus denen ein QR-Code besteht, können quadratisch bleiben oder zu Punkten, abgerundeten Reihen oder angeschrägten Formen werden, und die drei Eckquadrate und die Punkte in ihrem Inneren erhalten eigene Stile. Die Kreisform setzt den Code in ein rundes Feld und füllt den Raum darum mit Punkten, die dem Muster des Codes selbst nachgebildet sind. Ein Reset-Knopf neben den Reitern setzt alle Einstellungen zurück und behält den Text.

## Farben und Verläufe

Vorder- und Hintergrund nehmen jede Farbe an, und die Eckquadrate können eine eigene haben. Der Hintergrund kann auch transparent sein, für einen Code, der auf einem Foto oder einer farbigen Seite sitzt. Beide Ebenen nehmen einen Verlauf an, linear in einem beliebigen Winkel oder radial vom Mittelpunkt aus.

## Ein Logo in der Mitte

Ein Logo lässt sich auf den Reiter Style ziehen oder als Datei auswählen, und ein Regler bestimmt seine Grösse. Mit dem Ablegen steigt die Fehlerkorrektur auf H, die Stufe, die am meisten fehlende Daten wiederherstellen kann, denn die Module unter dem Logo fehlen, und der Scanner muss sie rekonstruieren. Stellt man die Stufe wieder tiefer, warnt der Reiter Settings, dass ein Logo die hohe Stufe braucht.

## Export und letzte Codes

Ein Code lässt sich als PNG, SVG, JPEG oder WebP herunterladen oder als PNG in die Zwischenablage kopieren. Der Reiter Settings legt die Exportgrösse fest, von 128 bis 512 Pixel, und den Rand um den Code. Jeder Download und jede Kopie landet ausserdem mit einem Vorschaubild in einer Liste Recent unter den Knöpfen. Sie behält die letzten zehn Codes im Browser, und ein Klick auf einen stellt seinen Text und alle Einstellungen wieder her.

## So ist es gebaut

Die Seite ist eine Next.js-App mit shadcn/ui auf Radix und Tailwind. [qr-code-styling](https://github.com/kozakdenys/qr-code-styling) zeichnet den Code als SVG, und [qr-scanner](https://github.com/nimiq/qr-scanner) decodiert die Bilder für den Scan-Test. Codes werden im Browser erzeugt und decodiert, der Text verlässt die Seite also nie.

### Wie gross das Logo sein darf

Ein QR-Code speichert seine Daten zusammen mit Reed-Solomon-Codewörtern zur Fehlerkorrektur, in einer von vier Stufen: L kann rund 7% der Codewörter wiederherstellen, M 15%, Q 25% und H 30%. Ein Logo verbraucht diesen Spielraum. qr-code-styling multipliziert die Grösseneinstellung mit dem Prozentsatz der Stufe und mit der Zahl der Module im Code und nimmt das Ergebnis als die grösste Zahl von Modulen, die das Logo verdecken darf. Dann räumt es den grössten Block unter dieser Zahl frei, mit einer ungeraden Anzahl Module in der Breite, damit er in der Mitte sitzt, und passt das Logo hinein.

Die Stufe verändert auch den Code selbst. Für `https://ysz.life`, 16 Bytes, bei der Standardeinstellung 0.35 für die Grösse:

| Stufe | Stellt wieder her | Symbol             | Platz für das Logo |
| ----- | ----------------- | ------------------ | ------------------ |
| L     | Rund 7%           | Version 1, 21 × 21 | 3 × 3 Module       |
| M     | Rund 15%          | Version 2, 25 × 25 | 5 × 5 Module       |
| Q     | Rund 25%          | Version 2, 25 × 25 | 7 × 7 Module       |
| H     | Rund 30%          | Version 3, 29 × 29 | 9 × 9 Module       |

Alle vier liessen sich im Scan-Test decodieren, weil eine tiefere Stufe das Logo verkleinert, damit es ins kleinere Budget passt.

### Welche Farben sich noch scannen lassen

Für Farben gibt es kein solches Budget. qr-code-styling zeichnet, was man ihm gibt, und ein Scanner braucht Kontrast zwischen den Modulen und dem Hintergrund. Ich habe Varianten des Standardcodes exportiert und jede durch den Scan-Test laufen lassen:

| Code                                                                                     | Scan-Test   |
| ---------------------------------------------------------------------------------------- | ----------- |
| Marineblau auf Weiss, der Standard                                                       | Besteht     |
| Marineblau auf transparentem Hintergrund                                                 | Besteht     |
| Weiss auf Marineblau                                                                     | Besteht     |
| Grau `#888888` auf Weiss                                                                 | Besteht     |
| Grau `#999999` auf Weiss und alles Hellere                                               | Fällt durch |
| Gelb `#ffd400` auf Weiss                                                                 | Fällt durch |
| Ein Verlauf von Marineblau zu blassem Lavendel `#e0e0ff`, die Ecken weiterhin marineblau | Fällt durch |

Der Decoder ist qr-scanner, das auf jsQR aufbaut, einer JavaScript-Portierung von Googles Bibliothek ZXing. Er läuft in einem Web Worker oder nutzt den eigenen `BarcodeDetector` des Browsers, wo es einen gibt, und der Dialog importiert ihn erst beim ersten Scan, sodass er der Seite nichts hinzufügt, bis ihn jemand braucht. Ein bestandener Test ist trotzdem nur das Ergebnis eines einzigen Decoders, und Handykameras unterscheiden sich; ein Code, der hier durchfällt, braucht darum mehr Kontrast, bevor er in den Druck geht.

### Ein Rendering pro Änderung

Der Generator wird mit `next/dynamic` und `ssr: false` geladen, und qr-code-styling wird erst nach dem Mount importiert. Jede Änderung an den Einstellungen baut dann eine neue Instanz und tauscht deren SVG in die Vorschau. Die Funktion `update()` der Bibliothek übernimmt neue Optionen in eine bestehende Instanz, aber ihr Deep Merge lieferte eine falsche Ausgabe, deshalb baut der Effekt stattdessen neu auf. Das kostet ein frisches Rendering pro Tastendruck oder Reglerschritt, bei einem Code von höchstens 512 Pixeln.

Beim Wiederherstellen eines zuletzt erstellten Codes werden die gespeicherten Einstellungen über die aktuellen Standardwerte gelegt, sodass sich auch ein Code wiederherstellen lässt, der vor einer neueren Option gespeichert wurde; die Standardwerte füllen die Felder, die ihm fehlen.
