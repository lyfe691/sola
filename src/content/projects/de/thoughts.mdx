# Eine Schreibseite mit Gästebuch

Auf [Thoughts](https://thoughts.ysz.life) schreibe ich das auf, was auf keine Projektseite passt. Es sind ein paar ruhige Textseiten: eine About-Seite, die Liste der Beiträge und ein Gästebuch, in dem jede Person eine Notiz hinterlassen kann. Die Seite basiert auf [Shu Dings Seite](https://shud.in).

## Seiten und Beiträge

Die Links stehen links vom Text in kleingeschriebener, kursiver Serifenschrift, und auf einem breiten Bildschirm bleiben sie beim Scrollen an ihrem Platz. Beim Wechsel zwischen den Seiten wird übergeblendet. Auf dem Handy rücken die Links in eine Reihe über dem Text.

Jeder Beitrag ist eine MDX-Datei im Repository, die ihren Titel, ihr Datum und ihre Beschreibung exportiert. Die Liste zeigt die Beiträge mit dem neuesten zuerst, wobei jeder Titel durch eine Punktreihe mit seinem Datum verbunden ist. Code in einem Beitrag wird auf dem Server von Shiki hervorgehoben, die Farben kommen also als fertiges HTML an, und der Titel eines Bildes wird auf einem breiten Bildschirm zu einer Randnotiz neben ihm.

Eine Adresse, die es nicht gibt, bekommt einen kurzen Vers.

## Das Gästebuch

Jede Person kann sich ohne Konto ins Gästebuch eintragen, mit einem optionalen Namen und einer Nachricht von höchstens 280 Zeichen. Die Einträge erscheinen mit dem neuesten zuerst, mit Datum und Uhrzeit, jeweils zehn auf einmal, und ein selbst geschriebener bekommt einen Link Delete, wenn Sie mit der Maus darüberfahren.

## So ist es gebaut

Thoughts ist eine Next.js-App auf Vercel. Die Beiträge werden aus MDX kompiliert und beim Build als statische Seiten gerendert. Das Gästebuch ist eine einzige Postgres-Tabelle, die ein einziger Route-Handler über `@vercel/postgres` liest und schreibt.

### Ins Gästebuch eintragen

Ein `POST` an `/api/guestbook` durchläuft drei Prüfungen der Reihe nach und schreibt nur, wenn alle bestanden sind:

1. **Das versteckte Feld ist leer.** Das Formular hat ein Feld `website`, das eine Person nie sieht und ein Bot, der Formulare ausfüllt, in der Regel schon, und jeder Wert darin führt zur Ablehnung der Anfrage.
2. **Die Nachricht passt.** Sie wird getrimmt und muss zwischen 1 und 280 Zeichen lang sein, und der Name wird auf 50 gekürzt.
3. **Der Absender schreibt nicht zu schnell.** Die Route sucht den neuesten Eintrag desselben Absenders und antwortet mit 429, wenn er weniger als 30 Sekunden alt ist.

Ein Absender wird an einem SHA-256-Hash der Adresse des Clients erkannt, die aus dem ersten Eintrag in `x-forwarded-for` stammt, und der Hash ist alles, was die Tabelle speichert. Er genügt, um denselben Absender ein zweites Mal wiederzuerkennen, und das brauchen die Ratenbegrenzung und die Löschprüfung weiter unten.

Das ist gekürzt: Der echte Handler hat einen zweiten Zweig, der die Einträge in einem Array im Arbeitsspeicher hält, wenn keine Datenbank konfiguriert ist, sodass die Seite in der lokalen Entwicklung auch ohne eine läuft.

### Moderation

Jede Zeile trägt zwei Flags, und zusammen entscheiden sie, wo sich ein Eintrag befindet:

| `approved` | `rejected` | Der Eintrag                                  |
| ---------- | ---------- | -------------------------------------------- |
| Ja         | Nein       | Erscheint in der öffentlichen Liste          |
| Nein       | Nein       | Wartet in der Admin-Warteschlange            |
| Beliebig   | Ja         | Ist verborgen, und die Zeile bleibt erhalten |

Ob ein neuer Eintrag beim Eingang genehmigt wird, bestimmt eine einzige Umgebungsvariable, die standardmässig auf Ja steht. Ist sie ausgeschaltet, warten neue Einträge in der Warteschlange, und wer einen Eintrag schreibt, sieht stattdessen einen Hinweis, dass er noch aussteht, und findet ihn nicht oben in der Liste.

Die Warteschlange ist eine durch ein Token geschützte Admin-Seite. Sie listet die ausstehenden Einträge mit dem ältesten zuerst auf, jeden mit einem Knopf zum Genehmigen und einem zum Ablehnen, und eine zweite Ansicht listet die genehmigten mit einem Löschen-Knopf auf. Das Ablehnen eines Eintrags setzt sein Flag und behält die Zeile. Die Ratenbegrenzung liest jede Zeile eines Absenders, deshalb zählt auch ein abgelehnter Eintrag zu den 30 Sekunden dieses Absenders.

### Den eigenen Eintrag löschen

Besucher haben keine Konten, deshalb braucht die Seite einen anderen Weg, um zu wissen, wer einen Eintrag geschrieben hat. Wenn der Browser einen Eintrag abschickt, speichert er die zurückgegebene ID in `localStorage`, und Einträge mit einer gespeicherten ID erhalten den Link Delete. Auf diese Liste verlässt sich der Server nicht. Seine Abfrage lautet `DELETE FROM guestbook WHERE id = … AND ip_hash = …`, sodass eine Zeile nur verschwindet, wenn die Anfrage von derselben gehashten Adresse kommt, die sie geschrieben hat. Der Kompromiss: Wer als Besitzer gilt, hängt vom Netzwerk ab. Über eine andere Verbindung wird der Link weiterhin angezeigt, und der Server verweigert das Löschen.
