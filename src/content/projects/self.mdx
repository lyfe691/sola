# Neofetch-style system info for Windows PowerShell

Self prints a picture and a column of system facts side by side in Windows PowerShell, the way [Neofetch](https://github.com/dylanaraps/neofetch) does on Linux. The picture can be any image file, redrawn in the terminal with coloured text characters, and the facts run from the Windows edition down to the disks.

## What it prints

On the left is a picture from the `images` folder, or any file passed with `--image`, scaled to a height and width given in characters. Each character cell holds two pixels, and every pixel keeps its own colour through 24-bit escape codes, so a photo or a drawing stays recognisable at a few dozen characters across. A braille mode draws finer dots instead, with one colour per cell.

On the right, under `user@host`, come the Windows edition, uptime, package counts from Chocolatey, Scoop and winget, the shell, screen resolution and theme, the processor, graphics card, memory and disks. The config decides which lines appear, and a colour theme sets the labels. The column ends with how long gathering the facts took and a row of the sixteen classic console colours.

## Installing and setting up

Self installs with one line in PowerShell:

```powershell
iwr -Uri "https://raw.githubusercontent.com/lyfe691/self/main/install.ps1" -UseBasicParsing | iex
```

The script downloads Self into a `self` folder in the user's profile, adds a `self.bat` launcher, puts the folder on the user's `PATH` and installs the Python packages with pip. It needs Python, but no administrator rights. `self --setup` then asks for the display type, the picture or drawing, the colour theme and, for pictures, the size, and saves the answers to `config.json`. `self --update` fetches the latest version and leaves the config, the cache and the user's own pictures alone.

## How it's built

Self is a small Python program in four modules: the display, the picture, the facts and the colour themes. Pillow reads and resizes the images, psutil reports memory, disks and uptime, and colorama provides the theme colours.

### Two pixels per character

A terminal cell is about twice as tall as it is wide. The half-block character `▀` fills the top half of a cell with the foreground colour and leaves the bottom half to the background colour, so a cell with both set holds two roughly square pixels. `rgb_to_ansi` builds the two escape codes, `\033[38;2;r;g;bm` for the foreground and `\033[48;2;r;g;bm` for the background, and block mode walks the image two rows at a time:

<CodeBlock
  code={`for y in range(0, img_height, 2):
      line = ""
      for x in range(img_width):
          r_upper, g_upper, b_upper = pixels[x, y]
          if y + 1 < img_height:
              r_lower, g_lower, b_lower = pixels[x, y + 1]
          else:
              r_lower, g_lower, b_lower = r_upper, g_upper, b_upper
          # '▀' character (upper half block)
          line += f"{rgb_to_ansi(r_upper, g_upper, b_upper)}{rgb_to_ansi(r_lower, g_lower, b_lower, bg=True)}▀{RESET}"
      lines.append(line)`}

/>

When height and width are equal, block mode doubles the width, because a square picture needs twice as many columns as rows. The 26 by 26 setting in the clip at the top becomes a 52 × 52 pixel image, resized by Pillow with nearest-neighbour sampling and printed as 26 rows of 52 characters.

### Padding by visible width

Those rows are long. Every cell carries a foreground code, a background code, the character and a reset, so one row of that picture runs to about 1,900 characters for 52 visible columns, and `len()` counts all of them. To line the facts up beside the picture, Self measures each row after a regular expression strips the escape codes, then pads the shorter rows with spaces to the widest.

### Eight dots per braille character

Braille mode trades colour for resolution. Unicode's braille block starts at U+2800 and encodes a cell's eight dots as bits of the offset, so any pattern on a 2 × 4 grid is a single character. The numbering is historical: dots 1 to 3 run down the left column and 4 to 6 down the right, and dots 7 and 8 were added later for eight-dot braille, so the bottom row is bits 6 and 7. The map from pixel position to bit reads:

<CodeBlock
  code={`bit_position_map = {
      (0, 0): 0, (1, 0): 3,
      (0, 1): 1, (1, 1): 4,
      (0, 2): 2, (1, 2): 5,
      (0, 3): 6, (1, 3): 7
  }`}
  fileName="image_handler.py"
  lang="python"
/>

The picture is converted to greyscale, a dot is raised where a pixel is darker than 127, and the whole cell takes the average colour of its eight pixels. A braille cell covers four times as many pixels as a block cell, but on a dark terminal the dots trace the dark parts of a picture and most of its colour is lost, which is why the README recommends block mode.

### A five-minute cache for the facts

The psutil library answers uptime, memory and disks directly. Most other lines come from short PowerShell commands: the Windows edition, the theme from the registry, the package counts. Each lookup starts its own `powershell.exe` with a two-second timeout, so one slow answer can't hold up the rest, and with `-NoProfile`, so the user's profile script doesn't run every time. The ten slower lookups run in parallel on a thread pool.

The result is kept in `cache/sysinfo.json` for five minutes, and `--no-cache` skips it. The "Executed in" line times this step: on my machine a fresh run takes about a second, and a cached one 0.00 seconds. Rendered pictures are cached too, for a day, keyed on the file's path and modification time, the size and the mode.
