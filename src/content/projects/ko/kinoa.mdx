# 무료로 보는 영화와 시리즈, 그리고 함께 보는 공간

[Kinoa](https://kinoa.to)는 영화와 시리즈를 무료로 볼 수 있는 사이트로, 플레이어를 중심으로 소셜 기능이 붙어 있습니다. 프로필, 피드, 댓글, 메시지, 그리고 함께 보는 방이 있습니다. 검색창 하나와 플레이어로 시작했고, 나머지는 릴리스를 거듭하며 하나씩 더해졌습니다.

## 볼 것 찾기

모든 것은 검색창 하나에서 시작합니다. 결과는 입력하는 동안 나타나며, 각 결과에는 포스터, 연도, 평점이 붙고, 가장 유력한 제목의 나머지 부분은 회색 글자로 자동 완성됩니다. 방향키로 목록을 오르내릴 수 있습니다. 검색창 아래 홈 화면에는 보던 작품과 이번 주에 다른 사람들이 보고 있는 작품이 나옵니다.

카드는 모두 마우스를 올리면 제자리에서 열립니다. 포스터가 작품의 아트워크로 넓어지고, 줄거리와 시청을 시작하는 버튼이 나타납니다.

## 재생하기

영화와 시리즈는 다른 사이트에서 임베드한 플레이어로 재생되며, 플레이어마다 모든 작품을 갖고 있지는 않습니다. 플레이어 아래 줄에는 현재 서버의 이름이 나오고, 서버마다 최고 화질이나 가장 안정적 같은 특기가 태그로 붙어 있습니다. 기본 서버가 로드되지 않으면 안내 문구가 한 번의 탭으로 다음 서버를 제안합니다. 휴대폰에서는 재생을 기기 자체의 전체 화면 플레이어로 바로 전환할 수 있습니다.

시리즈에는 시즌별 에피소드 선택기가 있고, 지금 보고 있는 에피소드가 강조됩니다.

## 함께 보기

방은 링크 하나입니다. 호스트가 작품을 고르고 방을 공유하면, 들어온 모두가 같은 장면을 보고, 플레이어 옆에는 채팅이 있습니다. 호스트가 일시 정지하거나 앞으로 건너뛰거나 에피소드를 바꾸면 방도 그대로 따라갑니다. 방 운영도 호스트가 맡습니다:

- **호스트 넘기기.** 호스트 자리는 방에 있는 다른 누구에게든 넘길 수 있고, 호스트의 탭이 닫히면 방이 아직 남아 있는 사람에게 호스트를 넘깁니다.
- **모더레이션.** 호스트는 사람을 내보내고 다시 들어오지 못하게 차단할 수 있습니다.
- **공개 범위.** 방은 공개 디렉터리에 올릴 수도 있고, 링크를 가진 사람에게만 열어 둘 수도 있습니다.

## 프로필, 피드, 메시지

플레이어 주위에는 작은 소셜 네트워크가 있습니다:

- **프로필.** 계정마다 핸들과 kinoa.to/@name의 공개 페이지가 생기고, 여기에 즐겨찾기, 관심 목록, 최근에 본 작품이 나옵니다. 스위치 하나로 프로필 전체를 비공개로 바꿀 수 있습니다.
- **피드.** 사람들은 서로를 팔로우하고, 작품에 좋아요를 누르고 댓글을 달며, 피드에는 Kinoa의 모든 사람이 남긴 댓글, 즐겨찾기, 팔로우가 최신순으로 나옵니다.
- **메시지.** 다이렉트 메시지에는 리액션, 수정과 삭제, 차단과 신고 기능이 있습니다.
- **알림.** 종 아이콘에 답글, 멘션, 좋아요, 팔로우가 생기는 대로 모이고, 팔로우한 작품이 공개되면 그 소식도 알려 줍니다.

## 디자인과 움직임

Kinoa는 크림과 에스프레소 색을 바탕으로 카라멜색 포인트를 준 따뜻한 팔레트를 쓰며, 라이트 테마와 다크 테마는 직접 고르지 않으면 시스템 설정을 따릅니다. 작은 움직임으로 방금 무슨 일이 있었는지 확인해 줍니다:

- 페이지가 스트리밍으로 들어오고, 각 부분은 자리 표시자가 있던 그 자리에 나타납니다.
- 사이드바가 부드럽게 열리고 닫힙니다.
- 거부된 폼은 잘못된 입력란을 흔듭니다.
- 대화상자는 크기가 툭툭 바뀌지 않고 부드럽게 바뀝니다.

시스템에서 동작 줄이기를 요청한 방문자에게는 이 모든 움직임이 물러납니다. Kinoa는 앱으로도 설치할 수 있습니다. 컴퓨터나 Android에서는 브라우저에서 바로, iPhone에서는 짧은 안내를 따라 설치합니다.

## 구현 방식

Kinoa는 대부분 서버 컴포넌트로 이루어진 Next.js 앱이고, 계정, 데이터베이스, 방이 돌아가는 실시간 채널에는 Supabase를 씁니다. Vercel에 배포되어 있고 next-intl로 번역합니다.

### 방을 하나의 시계에 맞추기

가장 어려운 제약은 임베드 플레이어입니다. 일시 정지하라거나 특정 시각으로 이동하라고 시킬 수가 없습니다. 그래서 호스트와 어긋난 게스트는 플레이어를 다시 로드하는데, 호스트의 위치에서 다시 로드에 걸리는 시간만큼 앞을 내다본 지점으로 로드합니다. 로드할 때마다 실제로 어디에 도착했는지를 측정해 다음 로드를 보정하고, 호스트보다 1초가 채 안 되는 만큼 뒤를 겨냥합니다. 장면을 망치는 것은 앞서는 쪽이지 늦는 쪽이 아니기 때문입니다.

<CodeBlock
  code={`/** Aim a touch behind the host — being early spoils, being late doesn't. */
  export const TARGET_DRIFT_SECONDS = -0.75
  /** Share of each landing error folded into the next lead estimate. */
  export const LEAD_LEARNING_RATE = 0.6
  export function anchorTargetFor(
    host: HostAnchor,
    now: number,
    leadSeconds: number
  ): AnchorTarget {
    if (!host.isPlaying) {
      return { time: Math.max(0, host.currentTime), play: false }
    }
    return {
      time: Math.max(0, projectPlayhead(host, host.at, now) + leadSeconds),
      play: true,
    }
  }
  export function nextLoadLead(lead: number, driftAtSettle: number): number {
    const error = driftAtSettle - TARGET_DRIFT_SECONDS
    const next = lead - error * LEAD_LEARNING_RATE
    return Math.min(
      MAX_LOAD_LEAD_SECONDS,
      Math.max(MIN_LOAD_LEAD_SECONDS, Number.isFinite(next) ? next : lead)
    )
  }`}

다시 로드하면 버퍼링이 한 번 생기므로, 게스트는 두 번 연속 검사에서 몇 초씩 어긋나 있을 때만 다시 로드하고, 몇 번 시도한 뒤에는 결정을 Catch up 버튼에 넘깁니다.

### 데이터베이스가 강제하는 규칙

규칙 두 가지는 앱이 아니라 데이터베이스에 있어서 어떤 클라이언트에서도 지켜집니다:

- **방을 조종하는 것은 호스트뿐입니다.** 방의 제어 채널에 걸린 행 수준 보안(row-level security) 정책입니다. 통합 테스트는 게스트로 로그인해 모든 제어 명령을 보내 보고, 호스트에게 그중 어떤 것도 도착하지 않는지 확인합니다.
- **핸들은 한 곳에서 확정됩니다.** 길이와 예약된 이름부터 모더레이션까지 모든 규칙을 데이터베이스 함수 하나가 맡고, 두 사람이 동시에 같은 이름을 차지하려 할 때는 유니크 인덱스가 결판을 냅니다.

### 서버 왕복 줄이기

필요한 것보다 훨씬 자주 실행되던 비용이 세 가지 있었습니다:

| 작업                             | 이전                                                 | 이후                                                      |
| -------------------------------- | ---------------------------------------------------- | --------------------------------------------------------- |
| 누가 로그인했는지 확인           | 영화 페이지에서 Supabase Auth 호출 3번, 피드에서 4번 | 렌더당 1번, 모든 헬퍼가 공유                              |
| 관심 목록 그리기                 | 목록의 작품마다 TMDB 요청 1번                        | 데이터베이스 쿼리 1번: 각 행이 카드 정보를 함께 담고 있음 |
| 열린 탭이 5분마다 하는 버전 확인 | 매번 서버리스 함수 실행                              | Vercel의 엣지 캐시                                        |

세션 확인은 로컬에서 디코딩하는 것이 아니라 네트워크를 거치기 때문에, 렌더당 한 번으로 줄인 것이 의미가 컸습니다.

### 번역을 빠짐없이 유지하기

모든 문자열은 영어가 원본입니다. CI의 검사가 다른 모든 언어 파일을 영어와 대조해 키가 빠졌거나 남아 있으면 실패하므로, 새 기능이 절반만 번역된 채 나갈 수 없습니다.
