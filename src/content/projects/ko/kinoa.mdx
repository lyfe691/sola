## 볼 것 찾기

홈 화면에는 헤드라인 하나와 검색창이 있고, 검색창 가장자리 너머로 작고 하얀 생물이 빼꼼 내다봅니다. 결과는 입력하는 동안 나타나고, 입력한 글자로 시작하는 첫 번째 제목은 나머지 부분이 회색 글자로 자동 완성됩니다. 생물은 커서를 따라 움직이고, 일치하는 결과가 없으면 어리둥절해하며, 입력란을 비우면 눈물을 글썽입니다.

어느 페이지에서든 검색 팔레트를 열 수 있습니다. 팔레트는 사이드바의 검색 입력란에서 커지며 펼쳐지고, 다 쓰고 나면 다시 그 안으로 줄어듭니다. 검색을 비롯한 몇 가지 기능은 키보드로도 쓸 수 있습니다.

| 단축키                   | 기능                               |
| ------------------------ | ---------------------------------- |
| `Ctrl K`, Mac에서는 `⌘K` | 어느 페이지에서든 검색 팔레트 열기 |
| `↑`와 `↓`                | 결과 사이를 이동                   |
| `Tab`                    | 회색 자동 완성 받아들이기          |
| `Enter`                  | 강조 표시된 결과 열기              |
| `Esc`                    | 검색 닫기                          |
| `D`                      | 라이트 테마와 다크 테마 전환       |
| `S`                      | 사이드바 보이기 또는 숨기기        |

## 장르와 언어로 둘러보기

Discover 페이지는 딱히 정해 둔 작품이 없을 때 둘러보는 곳입니다. 페이지를 열면 먼저 장르 타일이 나옵니다. 타일마다 그 장르의 포스터가 세 장씩 들어 있어 포인터를 올리면 부채꼴로 펼쳐지고, 그 아래로 숨은 명작, 극장 개봉 예정 영화 같은 줄이 이어집니다. 장르를 고르면 같은 페이지에서 타일이 결과로 바뀝니다. 결과 위의 필터는 주소에 담기므로(Science Fiction은 `/discover?genre=878`), 뒤로 가기를 누르면 필터를 하나씩 되돌아가고 공유한 링크도 같은 화면으로 열립니다. 언어 필터는 언어를 영어 이름으로도, 그 언어 자체의 이름으로도 찾아 주므로 “Korean”과 “한국어” 둘 다 됩니다.

## 함께 보기

방은 링크 하나입니다. 호스트가 작품을 고르고 방을 공유하면, 들어온 모두가 같은 장면을 보고, 플레이어 옆에는 채팅이 있습니다. 호스트가 일시 정지하거나 앞으로 건너뛰거나 에피소드를 바꾸면 방도 그대로 따라가고, 뒤처진 게스트에게는 Catch up 버튼이 나타납니다. 방 운영도 호스트가 맡습니다:

- **호스트 넘기기.** 호스트는 방에 있는 누구에게든 호스트 자리를 넘길 수 있습니다. 호스트가 방을 나가면 다음 사람에게 곧바로 넘어가고, 나가지 않은 채 호스트의 탭이 닫히면 몇 분 뒤 방에 남아 있는 사람이 이어받습니다.
- **모더레이션.** 호스트는 사람을 내보낼 수 있습니다. 방을 만든 사람은 호스트를 맡고 있는 동안 그 사람이 다시 들어오지 못하게 차단할 수도 있습니다.
- **공개 범위.** 공개 방은 Watch Together 페이지에 나열되고, 비공개 방에는 링크로만 들어올 수 있습니다.

## 프로필, 피드, 메시지

플레이어 주위에는 작은 소셜 네트워크가 있습니다:

- **프로필.** 핸들을 등록하면 계정에 `kinoa.to/@name` 페이지가 생기고, 여기에 커버 이미지, 소개글, 그리고 활동, 즐겨찾기, 관심 목록 탭이 있습니다. 스위치 하나로 탭을 비공개로 바꿀 수 있고, 이때도 이름, 소개글, 팔로워 수는 그대로 보입니다.
- **댓글.** 작품마다 스레드형 댓글이 있어 인기순이나 최신순으로 정렬할 수 있고, 댓글을 스포일러로 표시할 수도 있습니다.
- **피드.** Kinoa의 모든 사람이 남긴 새 댓글과 공개 프로필의 즐겨찾기, 팔로우를 최신순으로 보여 줍니다. 로그인하면 옆 패널에 관심 목록에 있는 작품의 공개일과 새 에피소드가 더해집니다.
- **메시지.** 다이렉트 메시지에는 리액션, 수정과 삭제, 차단과 신고 기능이 있습니다.
- **알림.** 종 아이콘에 답글, 멘션, 팔로우, 메시지가 생기는 대로 모이고, Titles 탭에는 관심 목록에서 곧 공개될 작품이 나옵니다.

## 사용자의 언어로

Kinoa는 사용자가 언어를 직접 고르기 전까지 브라우저의 언어를 따르고, 인터페이스의 모든 문자열이 번역되어 있습니다. 아랍어와 히브리어에서는 레이아웃 전체가 오른쪽에서 왼쪽으로 뒤집힙니다. 제목, 줄거리, 장르는 The Movie Database(TMDB)에 있는 한 방문자의 언어로 들어오고, 숫자와 상영 시간도 그 언어의 표기 방식대로 적힙니다. 다섯 가지 언어에서 Your Name 페이지의 윗부분은 이렇게 보입니다.

## 디자인과 움직임

Kinoa의 기본 모습은 회색 프레임 안에 흰 페이지가 놓인 형태이고, 다크 테마에서는 거의 검은색이며, 파란색은 포커스와 선택에만 씁니다. 직접 고르지 않으면 시스템의 라이트 또는 다크 설정을 따르고, Settings에서는 다른 테마를 고르거나 색과 대비를 직접 정할 수 있습니다. 사이드바에서 현재 페이지는 콘텐츠 패널과 이어진 탭으로 그려지고, 다른 항목을 고르면 탭이 그쪽으로 흘러가듯 옮겨 갑니다. 그 밖의 움직임은 작고, 방금 무슨 일이 있었는지 확인해 줍니다:

- 메뉴와 팝오버는 자신을 연 요소에서 커지며 펼쳐지고, 메뉴가 열리면 뒤의 페이지가 반투명 유리처럼 흐려집니다.
- 대화상자는 크기가 부드럽게 바뀌고, 단계가 넘어가도 버튼은 제자리를 지킵니다.
- 페이지가 스트리밍으로 들어오고, 각 부분은 자리 표시자가 있던 그 자리에 나타납니다.
- 거부된 폼은 잘못된 입력란을 흔듭니다.

시스템에서 동작 줄이기를 요청한 방문자에게는 움직임이 물러납니다. Kinoa는 앱으로도 설치할 수 있습니다. 컴퓨터나 Android에서는 브라우저에서 바로, iPhone에서는 짧은 안내를 따라 설치합니다.

## 구현 방식

Kinoa는 대부분 서버 컴포넌트로 이루어진 Next.js 앱이고, 계정, 데이터베이스, 방이 돌아가는 실시간 채널에는 Supabase를 씁니다. Vercel에 배포되어 있고 next-intl로 번역합니다.

### 방을 하나의 시계에 맞추기

가장 어려운 제약은 임베드 플레이어입니다. 일시 정지하라거나 특정 시각으로 이동하라고 시킬 수가 없습니다. 그래서 호스트와 어긋난 게스트는 플레이어를 다시 로드하는데, 호스트의 위치에서 다시 로드에 걸리는 시간만큼 앞을 내다본 지점으로 로드합니다. 로드할 때마다 실제로 어디에 도착했는지를 측정해 다음 로드를 보정하고, 호스트보다 1초가 채 안 되는 만큼 뒤를 겨냥합니다. 장면을 망치는 것은 앞서는 쪽이지 늦는 쪽이 아니기 때문입니다.

<CodeBlock

  export const TARGET_DRIFT_SECONDS = -0.75
  /** Share of each landing error folded into the next lead estimate. */
  export const LEAD_LEARNING_RATE = 0.6
  export function anchorTargetFor(
    host: HostAnchor,
    now: number,
    leadSeconds: number
  ): AnchorTarget {
    if (!host.isPlaying) {
      return { time: Math.max(0, host.currentTime), play: false }
    }
    return {
      time: Math.max(0, projectPlayhead(host, host.at, now) + leadSeconds),
      play: true,
    }
  }
  export function nextLoadLead(lead: number, driftAtSettle: number): number {
    const error = driftAtSettle - TARGET_DRIFT_SECONDS
    const next = lead - error * LEAD_LEARNING_RATE
    return Math.min(
      MAX_LOAD_LEAD_SECONDS,
      Math.max(MIN_LOAD_LEAD_SECONDS, Number.isFinite(next) ? next : lead)
    )
  }`}

다시 로드하면 버퍼링이 한 번 생기므로, 방은 꼭 필요할 때만 다시 로드를 요청합니다.

| 일어나는 일                          | 시점                                                    |
| ------------------------------------ | ------------------------------------------------------- |
| 호스트의 플레이어가 재생 위치를 보냄 | 5초마다, 그리고 재생, 일시 정지, 탐색할 때마다          |
| 게스트마다 어긋난 정도를 잼          | 1초마다                                                 |
| Catch up 버튼이 나타남               | 호스트와 4초 넘게 어긋났을 때                           |
| 게스트가 스스로 다시 로드함          | 그만큼 어긋난 검사가 두 번 연속될 때, 최대 20초에 한 번 |
| 스스로 다시 로드하기를 멈춤          | 3번 다시 로드해도 따라잡지 못했을 때                    |

방은 VidFast에서만 재생되는데, 이 방법에는 마지막으로 멈춘 곳이 아니라 지정한 곳에서 재생을 시작하는 플레이어가 필요하기 때문입니다.

### 방영일로 애니메이션 에피소드 짝짓기

Kinoa에서는 링크부터 시청 기록, 댓글까지 모든 것이 TMDB ID로 작품을 식별합니다. 그런데 애니메이션 플레이어는 그 대신 애니메이션 데이터베이스인 AniList의 ID와 에피소드 번호를 받고, 두 카탈로그는 작품을 나누는 방식도 다릅니다. TMDB는 Re:Zero의 85화 전체를 한 시즌으로 묶지만, AniList에는 파트마다 항목이 따로 있습니다.

| AniList 항목  | 화수 | TMDB 시즌 1 | 방영    |
| ------------- | ---- | ----------- | ------- |
| 시즌 1        | 25   | 1–25        | 2016    |
| 시즌 2        | 13   | 26–38       | 2020    |
| 시즌 2 파트 2 | 12   | 39–50       | 2021    |
| 시즌 3        | 16   | 51–66       | 2024–25 |
| 시즌 4        | 19   | 67–85       | 2026    |

그래서 Kinoa는 TMDB ID에 대응하는 AniList 항목을 찾고, 항목마다 방영일을 조회한 뒤, 앞뒤로 하루까지 허용해 날짜로 에피소드를 짝짓습니다.

날짜가 맞지 않는 에피소드는 확인된 짝 바로 옆에 있고, 그 구간에서 짝을 찾지 못한 에피소드 수가 두 카탈로그에서 같을 때만 짝을 짓습니다. 그렇지 않으면 짝 없이 일반 서버에서 재생합니다. 짝을 잘못 지으면 엉뚱한 에피소드가 재생되지만, 짝이 빠지면 서버만 바뀌기 때문입니다. 제가 확인한 인기 작품 30개에서는 이 방식으로 에피소드의 99~100%가 짝지어집니다.

### 데이터베이스가 강제하는 규칙

규칙 세 가지는 앱이 아니라 데이터베이스에 있어서 어떤 클라이언트에서도 지켜집니다:

- **방을 조종하는 것은 호스트뿐입니다.** 방의 제어 채널에 걸린 행 수준 보안(row-level security) 정책입니다. 통합 테스트는 게스트로 로그인해 내보내기와 동기화 같은 호스트 명령을 보내 보고, 호스트에게 그중 어떤 것도 도착하지 않는지 확인합니다.
- **내보낸 게스트는 즉시 끊깁니다.** Supabase Realtime은 클라이언트가 비공개 채널에 들어올 때 그 채널의 정책을 확인하고, 사용자 한 명만 채널에서 떼어 내는 호출은 없습니다. 그래서 방마다 채널 이름에 키를 넣고, 내보내기나 차단이 있을 때마다 이 키를 바꿉니다. 나머지 사람들은 새 키로 다시 들어오고, 내보낸 클라이언트는 아무것도 전송되지 않는 채널에 남겨집니다.
- **핸들은 한 곳에서 확정됩니다.** 길이와 예약된 이름부터 모더레이션, 변경 후 30일 대기 기간까지 모든 규칙을 데이터베이스 함수 하나가 맡고, 두 사람이 동시에 같은 이름을 차지하려 할 때는 유니크 인덱스가 결판을 냅니다.
