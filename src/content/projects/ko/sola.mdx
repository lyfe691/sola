## 홈 화면

홈 화면은 인사말과 다음으로 가는 길로 이루어져 있습니다. 인사말 속 이름은 제가 쓰는 이름인 Yanis, Sebi, lyfe691로 차례로 바뀌고, 이름을 누르면 다음 이름으로 넘어갑니다. 그 아래 문구도 순환하는데, 문장마다 흐릿한 상태에서 한 글자씩 쓰입니다. 인사말 위에는 제가 지금 작업 중인 것을 가리키는 작은 링크가 있습니다.

두 버튼은 유리 같은 질감으로, 가장자리에 은은한 빛의 테두리가 있고, 그 둘레를 훑고 지나가며 포인터 쪽으로 향하는 반짝임이 있습니다. 아래의 소셜 링크는 마우스를 올리면 이름과 브랜드 색으로 펼쳐집니다. 다른 페이지로 이동하면 현재 페이지가 흐려지며 사라지고, 다음 페이지가 같은 흐림에서 초점이 맞춰지며 나타납니다. 처음 방문하면 메뉴 옆의 안내가 제가 고른 테마와 배경, 그리고 그것을 바꾸는 위치를 알려 줍니다.

## 테마와 배경

오른쪽 위의 메뉴에서 사이트 전체의 모습을 바꿀 수 있습니다. 라이트, 다크, 시스템 설정 따르기 외에 저마다 팔레트를 가진 맞춤 테마가 있고, 하나에 마우스를 올리면 고르기 전에 작은 미리보기가 나타납니다. 새 테마는 0.5초도 안 되는 시간에 이전 테마 위로 서서히 번지며 바뀌고, 메뉴는 열린 채로 남아 있어서 다음 테마도 클릭 한 번이면 됩니다.

모든 페이지 뒤에는 움직이는 배경을 띄울 수 있습니다. 테마에서 색을 가져오는 WebGL 장면이고, 같은 메뉴에서 고릅니다. 부드러운 그라데이션도 있고, 비단이나 수채화처럼 움직이는 것도 있으며, 포인터를 따라다니는 유체도 하나 있습니다.

## 프로젝트

프로젝트 페이지는 카드 그리드입니다. 각 카드에는 프로젝트 고유의 색으로 만든 커버, 모서리의 노치에 들어간 날짜, 짧은 설명, 사용한 기술이 있습니다. 필터로 개인 프로젝트와 클라이언트를 위한 작업을 나눌 수 있고, 메뉴에서 추천순, 최신순, 오래된 순, 이름순으로 정렬할 수 있습니다.

순서가 바뀌면 화면에 보이는 모든 카드가 짧게 흐려지면서 그 자리를 이어받는 카드로 크로스페이드되어, 내용이 바뀌는 동안에도 그리드의 모양이 유지됩니다.

## 구현 방식

Sola는 TypeScript로 작성한 React 앱으로, Vite로 빌드하고 Tailwind CSS와 shadcn/ui 컴포넌트로 스타일을 입히고 Motion으로 애니메이션을 만듭니다. 배경은 three.js와 OGL로 그립니다. Vercel에 배포되어 있고, 서버리스 함수가 GitHub 활동과 Changelog의 커밋을 가져옵니다.

### 나타나기 시작하는 순간 그려진 것으로 집계되는 콘텐츠

사이트의 모든 등장 효과는 페이드이고, 예전에는 모두 opacity 0에서 시작했습니다. 화면에서 가장 큰 콘텐츠가 그려진 것으로 간주되는 시점인 Chrome의 Largest Contentful Paint(LCP)는 opacity 0으로 그려진 것을 건너뛰고, 페이드는 다시 페인트하지 않고 컴포지터에서 실행됩니다. 그래서 블록은 페이드가 끝난 뒤에야 집계되었고, 모든 페이지의 LCP에 0.7초의 글라이드가 그대로 얹혀 있었습니다. CPU를 4배 느리게 한 Chrome 트레이스에서 문의 페이지의 부제는 941 ms에 등장을 시작해 1536 ms에 집계되었습니다.

이제 등장 효과는 0.001에서 시작합니다. 흰색 위에서도 8비트 색상 채널의 한 단계보다 작은 값입니다. 겉보기에는 달라진 것이 없지만, 브라우저는 페이드가 시작되는 즉시 페인트를 집계합니다. 같은 트레이스에서는 다음과 같습니다:

| 페이지   | 가장 큰 페인트가 집계된 시점, 이전 | 이후    |
| -------- | ---------------------------------- | ------- |
| 문의     | 1536 ms                            | 804 ms  |
| 프로젝트 | 2764 ms                            | 1136 ms |
| 홈       | 2032 ms                            | 1120 ms |

### 하나의 라우트 목록

모든 페이지는 `src/config/routes.ts`의 항목 하나입니다. 경로, 불러올 코드, 레이아웃, 탭 제목이 그 안에 있습니다.

<CodeBlock
  code={`{
    path: "/projects",
    layout: "app",
    ...page(() => import("@/pages/Projects")),
    title: (t) => t.projects.title,
  },`}
  fileName="src/config/routes.ts"
  lang="ts"

라우터는 이 목록으로 렌더링하고, `index.html`에 작은 스크립트를 써 넣는 빌드 단계도 이 목록을 씁니다. 스크립트는 주소를 같은 목록과 대조해, 메인 번들이 아직 도착하는 중에 해당 페이지의 코드를 내려받기 시작합니다. 이전에는 번들 전체를 내려받아 실행한 뒤에야 페이지의 코드를 요청했습니다. 항목의 경로와 페이지가 더는 짝이 맞지 않으면 빌드가 실패하므로, 목록과 스크립트가 서로 어긋날 수 없습니다.

### 방문자당 하나의 언어

예전에는 방문자가 읽는 언어는 하나뿐인데도 모든 번역이 시작 번들에 포함되어 있었고, 그 크기는 minify 기준 156 KB였습니다. 지금도 영어는 대체 언어로 번들에 포함되고, 다른 언어는 각각 압축 시 약 11 KB의 별도 청크로 나뉘어 페이지의 코드와 함께 첫 렌더링 전에 가져오므로, 독일어 방문도 영어 방문보다 오래 기다리지 않습니다. 언어를 바꿀 때는 새 문구가 로드될 때까지 현재 문구가 화면에 유지됩니다.
