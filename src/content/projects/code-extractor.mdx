# A browser extension that saves a page and its files as a ZIP

[Website Code Extractor](https://chromewebstore.google.com/detail/website-code-extractor/foppgeakfpkdghmmmflmblcidoofpohm) is a Chrome and Edge extension that downloads the page in the current tab as one ZIP file. The archive holds the HTML and every stylesheet, script and image it references, in folders that mirror the servers they came from, and the HTML's links are rewritten to point at the saved copies. I built it in August 2024 to study how other sites are put together, and around 6,000 people use it now, according to the Chrome Web Store.

## Saving a page

The popup has one button. Clicking it reads the page in the active tab, fetches every file the page links to and packs everything into a ZIP named after the site, here `htmx.org.zip`, and Chrome then asks where to save it. On htmx.org, building the archive took under a second.

Pages that can't be scripted, such as `chrome://` and `edge://` pages, `about:` pages and other extensions' pages, get an error in the popup instead.

## What the archive holds

The ZIP opens to one folder named after the site, with `index.html` at its top. Every other file sits under a folder named after the server it came from, followed by that server's own path. htmx.org's stylesheet, scripts and images land under `htmx.org/htmx.org/`, and the script for its GitHub star button under `buttons.github.io/`, so two servers' files with the same name can't collide. The copy of htmx.org held 53 files and 2.4 MB, and the site's Atom feed was one of them: the page links it from a `<link>` tag, which the extension collects like a stylesheet.

## Opening the copy

Every stylesheet, script and image reference in the saved `index.html` points at the saved file, so the page opens straight from the folder with its styles and images in place. Links to other pages stay as they were, since the extension saves one page at a time.

## How it's built

The extension is plain JavaScript on Manifest V3. A popup page with one script does all the work, and JSZip builds the archive.

### Reading the page as it stands

The click runs a small function inside the tab through `chrome.scripting.executeScript`. Chrome serializes the function and runs it in the page, so it can't reach anything in the popup, and it hands back plain strings: the root element's `outerHTML` and the doctype. `outerHTML` leaves the doctype out, and a page saved without one opens in quirks mode, the legacy rendering mode browsers keep for pages written before the standards, so the doctype is serialized on its own and written back in front.

The saved HTML is therefore the page as it stands in the tab, after its scripts ran. A page that builds its markup in JavaScript is saved with the markup it built.

### Rewriting the links

Back in the popup, `DOMParser` turns the HTML into a document that stays inert: its scripts don't run and its images don't load. The popup then walks every `<link href>`, `<script src>` and `<img src>`:

<CodeBlock
  code={`function resolveResourceLinks(doc, baseUrl) {
      const resources = [];
      const elements = doc.querySelectorAll('link[href], script[src], img[src]');
      elements.forEach(element => {
          let attr;
          if (element.tagName === 'LINK') {
              attr = 'href';
          } else if (element.tagName === 'IMG' || element.tagName === 'SCRIPT') {
              attr = 'src';
          } else {
              attr = element.hasAttribute('src') ? 'src' : 'href';
          }
          let url = element.getAttribute(attr);
          if (url) {
              if (!url.startsWith('http')) {
                  url = new URL(url, baseUrl).href;
              }
              const urlObject = new URL(url);
              let path = urlObject.hostname + urlObject.pathname;
              path = path.startsWith('/') ? path.slice(1) : path;
              path = path.replace(/\\/\\//g, '/');
              resources.push({ url, path });
              element.setAttribute(attr, path);
          }
      });
      return resources;
  }`}
  fileName="popup.js"
  lang="js"
/>

Every reference is resolved against the tab's address first, so a root-relative `/css/site.css`, a relative `../img/logo.png` and a protocol-relative `//cdn.example.com/lib.js` all become full URLs. The hostname and path of that URL then do two jobs: they are the file's path inside the archive, and they replace the attribute's value in the HTML. The saved `index.html` sits at the top of the site's folder, so the new relative path leads to the saved file. Query strings are dropped along the way, since a cache-busting `?v=3` is not part of a file name.

Two tags from htmx.org as the server sent them, then as they read in the saved `index.html`, where `XMLSerializer` writes them back in XHTML style:

```text
<link rel="stylesheet" href="/css/site.css">
<script async defer src="https://buttons.github.io/buttons.js"></script>

<link rel="stylesheet" href="htmx.org/css/site.css" />
<script async="" defer="" src="buttons.github.io/buttons.js"></script>
```

### Fetching from other servers

Fetching a stylesheet from another server is what CORS stops an ordinary web page from doing. Extension pages are exempt for the hosts listed in the manifest's `host_permissions`, so the manifest asks for all `http` and `https` hosts next to `activeTab`, `scripting` and `downloads`. Chrome presents that at install time as permission to read and change data on every website, which is broad. The extension uses it for one thing: fetching, from the popup and only after a click, the files the open page already references.

The popup fetches them all at once with `Promise.all`. A fetch that fails is logged and skipped, so one missing image doesn't cost the whole archive. JSZip then builds the file, and `chrome.downloads.download` saves it, asking where first.
