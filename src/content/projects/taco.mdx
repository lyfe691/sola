# A website for my brother's dog, built to be reused

Taco is my brother's Pomeranian, and [takitwo.vercel.app](https://takitwo.vercel.app) is his website. I built it as a base for the next small site of this kind. The colours live in theme classes and every interface string in one JSON file per language, so the next site means new content and new values in those files while the components stay as they are.

## Colour themes

The palette button in the header opens the theme menu. Picking a theme recolours every page at once, from the links and buttons to the soft circles behind the photo, and the site remembers the choice for the next visit. Gotham is black and white, Night is navy with a blue accent, and every new visitor starts in Green.

## Languages

The site is written in English, Spanish and Japanese. On a first visit it picks the language that matches the browser and falls back to English, and the language button in the header switches it at any time. A choice made there is saved and wins on every later visit.

## How it's built

Taco is a Next.js app on the App Router, written in TypeScript. The components come from shadcn/ui, which builds on Radix, and are styled with Tailwind CSS. Framer Motion runs the page and navigation animation, and the site is deployed on Vercel.

### Themes are sets of CSS variables

shadcn/ui colours everything through tokens: classes like `bg-primary` and `border-border`. The Tailwind config maps each token to a CSS variable, so `primary` becomes `hsl(var(--primary))`, and a theme is a class that gives those variables different HSL values. Green sits on `:root`, and the other themes follow the same pattern as Sky, shown here abridged:

<CodeBlock
  code={`.theme-sky {
    --background: 210 50% 98%;
    --foreground: 210 50% 16%;
    --primary: 210 80% 50%;
    --primary-foreground: 355 100% 100%;
    --secondary: 210 33% 96%;
    --muted-foreground: 210 5% 45%;
    --border: 210 20% 90%;
    --ring: 210 80% 50%;
  }`}
  fileName="app/globals.css"
  lang="css"
/>

Because the pages colour themselves through the tokens, a new theme is one more class and an entry in the theme menu. Night is the class `dark`, the one Tailwind's `dark:` variant looks for. Gotham is dark as well but has a class of its own, so the prose styles for blog posts name both `.dark` and `.theme-gotham`.

### No flash of the wrong theme

[next-themes](https://github.com/pacocoursey/next-themes) puts the chosen theme's class on `<html>` and keeps it in `localStorage`. The class has to be in place before the first paint, or a returning visitor who picked Night would see the page flash green first. The library handles this with a small inline script that reads the stored theme and sets the class before React hydrates.

That is why `<html>` carries `suppressHydrationWarning`: its class in the browser differs from the server's HTML on purpose. The theme button has the same problem on a smaller scale. It shows the current theme's icon, a flower for Cherry and a moon for Night, and since the server can't know the theme, it renders the default palette icon until it has mounted.

### The English file is the type

The interface text lives in `lib/i18n/en.json`, `es.json` and `ja.json` as nested objects, and components look strings up by dot path: `t('home.aboutSection.title')` walks down whichever tree is active. The map that holds the language files is typed as `typeof en`, so a Spanish or Japanese file that is missing a key shows up as a type error in the editor.

On a visit, the provider first checks `localStorage` for a language picked earlier. If there is none, it asks the browser:

<CodeBlock
  code={`import { defaultLanguage, languages } from './languages';
  import en from './en.json';
  import es from './es.json';
  import ja from './ja.json';
  export type TranslationJSON = typeof en;
  type TranslationsType = { [key: string]: TranslationJSON };
  const translations: TranslationsType = { en, es, ja };
  const fallbackLanguageCode = 'en';
  export function detectUserLanguage(): string {
    if (typeof window !== 'undefined' && typeof navigator !== 'undefined') {
      const browserLang = navigator.language || navigator.languages[0];
      const langCode = browserLang.split('-')[0];
      return languages.some(lang => lang.code === langCode)
        ? langCode
        : fallbackLanguageCode;
    }
    return fallbackLanguageCode;
  }`}
  fileName="lib/i18n/index.ts"
  lang="ts"
/>

`navigator.language` returns a tag like `es-MX`. The function keeps the part before the hyphen and uses it if the site has that language, English otherwise. All of this runs in the browser after the page has loaded, which keeps every page static: the HTML is prerendered once and the URLs are the same in every language.

Adding a language takes a JSON file, an import that puts it in the map, and an entry in `languages.ts` with a code, a display name and a flag. The language menu is built from that list, so it needs no change of its own.
