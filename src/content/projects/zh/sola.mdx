## 首页

首页是一句问候，加上通往其他页面的入口。问候里的名字会轮流换成我用的几个名字：Yanis、Sebi 和 lyfe691，点它就会跳到下一个。下面那一行文字也会轮换，每句话都从模糊中一个字一个字地拼出来。问候语上方有一个小链接，指向我目前在做的事。

两个按钮是玻璃质感的，边缘有一圈柔和的光边，还有一道绕着按钮扫过、并朝向指针转动的高光。下方的社交链接在悬停时会展开，显示出名称和品牌色。切换到另一个页面时，当前页面会模糊淡出，下一个页面再从同样的模糊中变清晰。首次访问时，菜单旁边有一条提示，说明我选了哪套主题和背景，以及在哪里可以更换。

## 主题与背景

右上角的菜单可以改变整个网站的外观。除了浅色、深色和跟随系统，还有各自配色的自定义主题，悬停在某个主题上会先显示一个小预览，再由你决定是否选用。新主题会在不到半秒内在旧主题之上渐渐显现，菜单保持打开，所以下一个只需点一下。

每个页面后面都可以运行一个动画背景，也就是一个从主题取色的 WebGL 场景，同样在这个菜单里选择。有些是柔和的渐变，有些像丝绸或水彩一样流动，还有一个是跟着指针走的流体。

## 实现方式

Sola 是一个用 TypeScript 写的 React 应用，用 Vite 构建，用 Tailwind CSS 和 shadcn/ui 组件做样式，用 Motion 做动画。背景由 three.js 和 OGL 绘制。它部署在 Vercel 上，由 Serverless 函数去获取 GitHub 活动和更新日志的提交记录。

### 内容一开始出现就算作已绘制

网站上的每一次入场都是淡入，而且过去每一次都从 opacity 0 开始。Chrome 的最大内容绘制（Largest Contentful Paint，LCP）指的是屏幕上最大的一块内容被算作已绘制的那一刻，它会跳过以 opacity 0 绘制的任何内容，而淡入是在合成器上运行的，不会再次绘制。所以一个内容块要等淡入结束才会被计入，每个页面的 LCP 都背着 0.7 秒的滑行时间。在 CPU 降速 4 倍的 Chrome 跟踪记录里，联系页的副标题在 941 ms 时开始显现，在 1536 ms 时才被计入。

现在入场从 0.001 开始，即便在白色背景上，这也不到 8 位颜色通道的一个级差。看上去没有任何不同，但浏览器在淡入开始的那一刻就把这次绘制计入。在同一份跟踪记录里：

| 页面   | 最大绘制被计入的时刻，之前 | 之后    |
| ------ | -------------------------- | ------- |
| 联系页 | 1536 ms                    | 804 ms  |
| 项目页 | 2764 ms                    | 1136 ms |
| 首页   | 2032 ms                    | 1120 ms |

### 一份路由清单

每个页面都是 `src/config/routes.ts` 里的一个条目：它的路径、要加载的代码、布局和标签页标题。

<CodeBlock
  code={`{
    path: "/projects",
    layout: "app",
    ...page(() => import("@/pages/Projects")),
    title: (t) => t.projects.title,
  },`}
  fileName="src/config/routes.ts"
  lang="ts"
/>

路由器按这份清单渲染，一个构建步骤也是如此，它会往 `index.html` 里写入一小段脚本。这段脚本用同一份清单去匹配地址，在主包还在下载的时候就开始下载对应页面的代码；而在此之前，页面的代码要等整个主包下载并运行完才会被请求。如果某个条目的路径和页面不再配对，构建就会失败，所以清单和脚本不会各走各的。

### 每位访客一种语言

过去所有翻译都打包进启动包里，minify 后有 156 KB，而一位访客只会读其中一种。英语仍然作为后备语言打包在内，其他每种语言都是独立的一个块，压缩后约 11 KB，在首次渲染之前和页面的代码一起获取，所以德语访客等待的时间并不比英语访客长。切换语言时，当前的文字会一直留在屏幕上，直到新的文字加载完成。
