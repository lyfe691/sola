# 用自己的 API 密钥运行的多服务商 AI 聊天应用

[Luma](https://luma.ysz.life) 是一款聊天应用，面向已经在一家或多家模型服务商那里购买了 API 访问权限的人。密钥只需添加一次，每段对话各选一个模型，每个请求都会用你的密钥发往对应的服务商。

## 选择模型

输入框里的模型按钮会打开一个选择器，列出 Luma 提供的全部模型，并按服务商分组。一列服务商标志可以在各组之间跳转，搜索框会随着输入实时筛选，小图标标出每个模型支持的能力，例如推理、图片输入、工具调用和 PDF。点一下星标，就能把模型加入这一列上的收藏列表。

每段对话都有自己的模型，所以这段对话可以用 Claude，下一段可以用 GPT-5 Mini。服务商还没有密钥的模型带一把锁，选中这样的模型时，输入框上方会出现一条提示，指出缺少哪个密钥，旁边有一个按钮可以打开设置。

## 提问

输入框可以接收文字、图片，以及 PDF、CSV 和 Markdown 之类的文件，可以粘贴、拖放进去，也可以从加号菜单里选择。同一个菜单还能为下一条消息设定模式：

- **Create image**：请模型用一张图片来回答。
- **Web search**：让模型上网查找资料，并注明来源。
- **Study and learn**：请模型有条理地讲解，并配上详细解答的例题。

## 回答

回复以 Markdown 的形式逐步流入。代码块带语法高亮，配有复制和下载按钮，数学公式和图示就地渲染。模型在作答前先推理时，推理过程会折叠成回复上方的一行“Thought for N seconds”，而 Claude 模型无需打开任何开关就能使用扩展思考。网络搜索得来的回答，会在用到某条来源的句子旁边，以小标签的形式标出这条来源。

## 编辑、重试与查找对话

对话里的任何内容都不会被覆盖。编辑自己发出的消息，会在旧版本旁边新增一个版本，下面跟着一条新的回复，消息下方的箭头可以在各个版本之间切换。重试一条回答，在回复这一侧也是同样的做法，而且重试菜单可以把问题交给另一个模型，于是两个模型对同一条消息的回答只隔着一次箭头切换。

新对话的标题由一个小而便宜的模型用你的某把密钥生成。侧边栏列出这些对话，置顶的排在最前，每段对话都可以在那里置顶、重命名或删除。设置里可以把你的全部对话导出为下载文件，也可以将它们删除。常用操作都有快捷键，Windows 上用 Ctrl，Mac 上用 ⌘：

| 快捷键               | 作用                     |
| -------------------- | ------------------------ |
| Ctrl K               | 搜索所有对话，按日期分组 |
| Ctrl Shift O         | 新建对话                 |
| Ctrl M               | 打开模型选择器           |
| Ctrl U               | 添加文件                 |
| Ctrl Shift S         | 显示或隐藏侧边栏         |
| Shift Esc            | 跳到消息输入框           |
| Ctrl Shift Backspace | 删除当前打开的对话       |

## 你的 API 密钥

设置里每个服务商各占一行，每行都带一个链接，指向获取密钥的页面。Luma 在保存新密钥之前，会先拿它向服务商试一下，所以服务商拒绝的密钥当场就会被拒绝。密钥先加密再存储，浏览器只会知道哪些服务商有密钥。

## 实现方式

Luma 是一个基于 React 19 的 Next.js 16 应用。回复由 Vercel AI SDK 流式输出，它通过各服务商自己的软件包连接到每一家服务商；账号、对话和上传的文件存放在 Supabase 里；启动页上的线条是一段 Three.js 着色器。

### 对话是一棵树

每条消息是一行数据，带有一个 `parent_id`，每段对话再多存一个指针 `active_leaf_id`，指向屏幕上那条消息链的最后一条消息。这条消息链是推导出来的：从当前叶子出发，沿父指针一路向上走到根，再反转顺序。编辑或重试会在同一个父节点下新增一个兄弟节点，遍历时会给每条拥有同角色兄弟的消息标上它在其中的位置，消息下方的箭头读取的就只有这个。

<CodeBlock
  code={`export function buildTimelineMessages(
    graph: ChatGraph,
    activeLeafId: string
  ): UIMessage[] {
    const path = getPathToLeaf(graph, activeLeafId)
    if (path.length === 0) return []
    return path.map((node) => {
      const siblings = (graph.childrenByParentId.get(node.parentId) ?? []).filter(
        (candidate) => candidate.role === node.role
      )
      const branchCount = siblings.length
      const branchIndex = Math.max(
        0,
        siblings.findIndex((candidate) => candidate.id === node.id)
      )
      return {
        id: node.id,
        role: node.role,
        parts: node.parts,
        metadata: {
          createdAt: node.createdAt,
          ...(branchCount > 1
            ? ({
                branchCount,
                branchIndex,
                isActiveBranch: true,
              } satisfies ChatBranchMetadata)
            : {}),
        },
      } satisfies UIMessage
    })
  }`}
  fileName="lib/chat-tree.ts"
  lang="ts"
/>

切换版本是一次服务端调用：取下一个兄弟节点，顺着最新的子节点一路走到叶子，再把这片叶子存为当前叶子。这种设计的代价是，打开一段对话就要读取其中的每一条消息，包括你没在看的那些分支。作为交换，这些消息通过一次查询就能全部取回，用的是建立在对话和创建时间上的索引，而这棵树的代码是浏览器和服务器共同导入的纯 TypeScript。

### 从模型 ID 到服务商客户端

模型 ID 自带服务商前缀，例如 `anthropic:claude-opus-4-6`。聊天路由会拿这个 ID 去对照模型目录，目录里没有就回退到默认模型，所以浏览器无法请求 Luma 没有列出的模型。这个前缀决定用哪把用户密钥（只为这一次请求解密），以及用哪个服务商的 AI SDK 软件包；软件包通过动态 `import()` 加载，这样一次请求只会引入它所需要的那个 SDK。提供 OpenAI 兼容 API 的服务商会复用 OpenAI 的软件包，只是换上自己的 base URL，所以新增一家只需在目录里加一条记录。

### 密钥的存储

每把密钥用 AES-256-GCM 加密，每次都使用全新的随机 IV，并以 IV、密文和认证标签三部分存储。GCM 会对密文做认证，所以数据库里被改动过的值会解密失败，而不会变成另一把密钥。这保护的是泄露的数据库转储里的密钥。服务器必须用明文密钥去调用服务商，所以它能解密自己存的每一把密钥，同时握有数据库和主密钥的人也可以。

### 回传给模型的内容

存下来的回复保留屏幕上显示的一切：推理、文字、工具调用及其结果。下一次请求所带的历史记录由服务器根据这棵树重建，并且会先去掉其中三样东西：

| 回复的部分   | 回传的形式                   | 原因                                                           |
| ------------ | ---------------------------- | -------------------------------------------------------------- |
| 生成的图片   | 文字 `[image was generated]` | 否则 base64 数据会跟着之后的每一次请求一起发送                 |
| 推理         | 什么都不回传，只留在屏幕上   | OpenAI 的 Responses API 可能拒绝从历史记录中重放的推理项       |
| 服务商元数据 | 什么都不回传                 | 它指向某一家服务商之前的响应，所以一条消息链可以中途更换服务商 |

附件保存在私有存储桶里，每次请求都会为它们签发新的链接，十分钟后失效。
