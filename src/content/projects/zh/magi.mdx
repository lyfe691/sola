# 一个用 Rust 写的 TCP 和 UDP 端口扫描器

magi 是我用 Rust 写的命令行端口扫描器。它做的是连接扫描：每一次探测都是通过操作系统的套接字发出的普通 TCP 连接或 UDP 数据报，所以在 Linux、macOS 和 Windows 上以普通用户身份就能运行。它只报告自己真正观察到的端口状态，遇到无法测试的端口时也会如实说明。

## 扫描一台主机

你给 magi 一个目标和要探测的端口。开放的端口会列在各自的主机之下，并附上常见的服务名称；扫描时间较长时，计数器会显示已经探测了多少个端口、其中有多少个是开放的。上面那次运行的对象是 45.33.32.156，也就是 scanme.nmap.org，这是 Nmap 项目专门为测试扫描器而维护的一台主机，耗时约一秒。

目标可以有三种形式：

| 目标      | 示例              | magi 的做法                          |
| --------- | ----------------- | ------------------------------------ |
| 主机名    | `scanme.nmap.org` | 解析主机名，并扫描它返回的每一个地址 |
| IP 地址   | `45.33.32.156`    | 扫描该地址，不做 DNS 查询            |
| CIDR 子网 | `192.168.1.0/24`  | 扫描其中的每台主机，最大到 /16       |

设置 /16 这个上限，是为了不让输错的前缀变成数百万次探测。其余都是选项：

| 选项                  | 作用                                       | 默认值   |
| --------------------- | ------------------------------------------ | -------- |
| `-p`, `--ports`       | 要探测的端口，可以是列表、范围，或两者混用 | `1-1024` |
| `-c`, `--concurrency` | 同时进行的探测数                           | 512      |
| `-t`, `--timeout`     | 每次探测等待应答的时间，单位为毫秒         | 1000     |
| `-r`, `--rate`        | 每秒最多发起的探测数                       | 不设上限 |
| `-b`, `--banner`      | 读取每个开放服务发来的第一行               | 关闭     |
| `-u`, `--udp`         | 探测 UDP，而不是 TCP                       | TCP      |
| `-j`, `--json`        | 以 JSON 格式输出结果                       | 表格     |

<CodeBlock
  code={`magi 192.168.1.0/24 --ports 22,80,443      # a whole subnet, grouped by host
  magi 10.0.0.5 --ports 1-65535 -c 1024      # every port, 1024 probes in flight
  magi 192.168.1.1 --ports 53,123,161 --udp  # UDP instead of TCP
  magi scanme.nmap.org -p 22,80 --json | jq  # JSON on stdout, progress on stderr`}

## 面向脚本的输出

所有给人看的内容都输出到 stderr：开启扫描的那一行、计数器和各种警告。只有当 stderr 是终端时才会出现计数器。加上 `--json` 后，stdout 输出的是开放端口的 JSON 数组，其中包含它们的地址、协议、状态和 banner，所以结果可以直接通过管道交给 jq 或其他程序。

## UDP

`--udp` 会改为探测 UDP。UDP 没有握手，所以 magi 发送一个空数据报，再根据主机的反应来下判断：

| 主机的反应           | magi 的报告                |
| -------------------- | -------------------------- |
| 回复                 | `open`                     |
| 回以 ICMP 端口不可达 | 判为关闭，并且不列出该端口 |
| 一直沉默到超时       | `open\|filtered`           |

沉默是有歧义的：一个忽略空数据报的开放服务，和一个把它丢弃的防火墙，从外面看没有区别，所以 magi 不会二选一。在这次运行中，53 和 161 返回了关闭，因此没有列出，而 123 在整整一秒里都保持沉默。

## 无法测试的端口

一次 TCP 探测有四种结局，其中只有两种能说明这个端口的情况：

| 连接的结果                   | magi 把端口计为 | 原因                             |
| ---------------------------- | --------------- | -------------------------------- |
| 建立成功                     | 开放            | 有东西在监听                     |
| 被拒绝，或超时               | 未开放          | 主机回答了“不”，或者根本没有回答 |
| 因进程用完了文件描述符而失败 | 未测试          | 探测根本没有运行                 |
| 因其他任何原因而失败         | 未测试          | 什么都没有到达这个端口           |

未测试的端口不会被并入“关闭”的计数。扫描结束时会给出一条警告，说明有多少个这样的端口以及原因；如果原因是文件描述符用完，它会提示调低 `--concurrency` 或调高打开文件数的上限。在下面的视频里，scanme.nmap.org 解析出一个 IPv4 地址和一个 IPv6 地址。在没有 IPv6 路由的网络上，发往 IPv6 地址的连接会在什么都没发出之前就以“network unreachable”失败，所以它的三个端口被报告为未测试。

## 实现方式

magi 是一个小型库，外面只包着一层很薄的可执行程序。`main.rs` 负责解析参数、展开目标并打印结果，`scanner.rs` 则包含扫描本身、banner 抓取、UDP 和服务名称。它运行在 tokio 上，用 clap 处理选项，用 serde 处理 JSON。GitHub Actions 在每次推送时运行 rustfmt、clippy 和测试，cargo-dist 则构建发行版压缩包和安装脚本。网站用 Next.js 做成，翻译由 next-intl 完成。

### 同时进行的探测数量固定

对一个 /24 网段扫描 1 到 1024 号端口，大约是 26 万次探测；如果预先为每一次都创建一个任务，所有任务就会同时占着内存。所以扫描循环改为在创建每个探测之前先取得一个信号量许可，一旦有 `--concurrency` 个探测在进行，它就等其中一个完成。许可会移进任务，并在探测结束时释放，循环也会边走边收集已完成的探测，因此无论扫描多大，存活的任务数量都有上限。以下摘自 `scan()`，有删节：

<CodeBlock
  code={`let permits = config.concurrency.clamp(1, MAX_CONCURRENCY);
  let limiter = Arc::new(Semaphore::new(permits));
  let mut tasks = JoinSet::new();
  let mut summary = ScanSummary::default();
  for &target in targets {
      for &port in ports {
          let permit = Arc::clone(&limiter)
              .acquire_owned()
              .await
              .expect("semaphore stays open for the duration of the scan");
          tasks.spawn(async move {
              let _permit = permit;
              probe(target, port, timeout_dur, grab_banner, protocol).await
          });
          while let Some(joined) = tasks.try_join_next() {
              collect(&mut summary, &mut progress, joined);
          }
      }
  }`}
  fileName="src/scanner.rs"
  lang="rust"
/>

可选的速率上限是一个 tokio interval，在每次创建探测之前触发一次。信号量限制同时运行的探测数，interval 限制每秒开始的探测数，并且错过的 tick 会被顺延，所以一段缓慢的时间之后，绝不会突然放出一批探测去追赶进度。

### 区分关闭与未测试

“无法测试的端口”一节下的那张表，对应的就是一个函数。它对连接失败时得到的错误进行分类，凡是既不是拒绝也不是超时的，都会变成两种未测试类型之一：

<CodeBlock
  code={`fn classify_connect_error(e: &io::Error) -> ProbeOutcome {
      match e.kind() {
          ErrorKind::ConnectionRefused | ErrorKind::TimedOut => ProbeOutcome::NotOpen,
          _ if is_fd_exhaustion(e) => ProbeOutcome::Untestable(Untestable::OutOfDescriptors),
          _ => ProbeOutcome::Untestable(Untestable::Other),
      }
  }`}
  fileName="src/scanner.rs"
  lang="rust"
/>

因为扫描器是一个库，集成测试直接对回环地址上的套接字调用真正的 `scan()`。其中一个测试把进程的打开文件数上限降到 128，在 300 个探测同时进行的情况下依次用 TCP 和 UDP 扫描 400 个本地端口，并检查两次结果都统计了未测试的端口，且都把描述符上限指为原因。

### 不用原始套接字的 UDP

要看到 ICMP 端口不可达，通常需要原始套接字，也就需要 root 权限。magi 在发送之前先把它的 UDP 套接字 connect 到目标上，这样只会接收那一个对端的回复，并且让操作系统在下一次接收时把那条 ICMP 消息报告为 `ConnectionRefused` 错误。“关闭”的判断就取决于操作系统是否把这些错误传回来，Linux 能可靠地做到这一点。macOS 和 Windows 会对 ICMP 限速，所以在它们上面，有些关闭的端口会显示成 `open|filtered`。

### 来自不可信主机的 banner

加上 `--banner` 后，magi 会从每个开放端口读取最多 512 字节，并保留第一行。这段文字来自一台你无法控制的主机，最终会出现在你的终端里，所以打印之前会去掉每一个控制字符。否则，banner 里的一段原始转义序列就可能清屏、改掉窗口标题，或覆盖之前的输出；有一个单元测试会送入一段 ANSI 清屏序列，以检查输出的只有可打印文字。
