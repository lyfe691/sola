# 自分の API キーで動く、複数プロバイダー対応の AI チャット

[Luma](https://luma.ysz.life) は、すでに 1 社以上のモデルプロバイダーで API の利用料を払っている人のためのチャットアプリです。キーを一度追加しておけば、チャットごとにモデルを選べて、すべてのリクエストはそのプロバイダーに、あなたのキーで送られます。

## モデルを選ぶ

入力欄のモデルボタンを押すと、Luma が提供するすべてのモデルをプロバイダーごとにまとめたピッカーが開きます。プロバイダーのロゴを並べたレールからグループへ一気に移動でき、検索ボックスは入力するたびに絞り込みます。各モデルが対応する機能は、推論、画像入力、ツール使用、PDF など、小さなアイコンで示されます。星を付けたモデルは、レールのお気に入りリストに加わります。

モデルはチャットごとに保持されるので、ある会話は Claude、次の会話は GPT-5 Mini、というように使い分けられます。プロバイダーのキーがまだないモデルには鍵のマークが付いていて、それを選ぶと、入力欄の上に足りないキーの名前を挙げた案内が表示され、設定を開くボタンも付きます。

## 質問する

入力欄には、テキストと画像、それに PDF、CSV、Markdown などのファイルを渡せます。貼り付けても、ドロップしても、プラスメニューから選んでも構いません。同じメニューで、次のメッセージのモードも設定できます。

- **Create image** は、モデルに画像で答えさせます。
- **Web search** は、モデルに調べものをさせ、出典を示させます。
- **Study and learn** は、例題を交えた体系的な解説を求めます。

## 回答

返信は Markdown としてストリーミングで届きます。コードブロックはハイライトされ、コピーとダウンロードのボタンが付き、数式や図はその場で描画されます。モデルが答える前に推論する場合、その推論は返信の上の「Thought for N seconds」の行に折りたたまれ、Claude のモデルでは、何も切り替えなくても拡張思考が使えます。Web 検索の回答では、出典が、それを使った文のそばに小さなチップとして付きます。

## 編集、再試行、チャットの検索

会話の中のものは、何も上書きされません。送ったメッセージを編集すると、古いバージョンの隣に新しいバージョンが加わり、その下に新しい返信が付きます。メッセージの下の矢印で、バージョンを行き来できます。回答の再試行も、返信側で同じことをします。再試行メニューからは質問を別のモデルに送ることもできるので、同じメッセージに対する 2 つのモデルの回答が、矢印 1 つ分の距離に並びます。

新しいチャットのタイトルは、あなたのキーのどれかで動く、小さくて安価なモデルが付けます。サイドバーには、ピン留めしたものを先頭にチャットが並び、そこから各チャットをピン留め、名前変更、削除できます。設定からは、すべてのチャットをダウンロードとして書き出すことも、削除することもできます。よく使う操作にはショートカットがあり、Windows では Ctrl、Mac では ⌘ を使います。

| ショートカット       | 動作                                           |
| -------------------- | ---------------------------------------------- |
| Ctrl K               | すべてのチャットを日付ごとにまとめて検索します |
| Ctrl Shift O         | 新しいチャットを始めます                       |
| Ctrl M               | モデルピッカーを開きます                       |
| Ctrl U               | ファイルを添付します                           |
| Ctrl Shift S         | サイドバーを表示または非表示にします           |
| Shift Esc            | メッセージ入力欄に移動します                   |
| Ctrl Shift Backspace | 開いているチャットを削除します                 |

## API キー

設定にはプロバイダーごとの行があり、それぞれにキーを取得するページへのリンクが付いています。Luma は新しいキーを保存する前にそのプロバイダーで試すので、プロバイダーに拒否されたキーはその場で受け付けられません。キーは暗号化してから保存され、ブラウザに伝わるのは、どのプロバイダーにキーがあるかだけです。

## 実装

Luma は React 19 上で動く Next.js 16 のアプリです。返信のストリーミングは Vercel AI SDK が担い、各プロバイダーへは、そのプロバイダー専用のパッケージを通じてつなぎます。アカウント、チャット、アップロードされたファイルは Supabase に保存され、スタート画面の筋は Three.js のシェーダーです。

### 会話は木構造

すべてのメッセージは `parent_id` を持つ 1 行で、チャットはもうひとつのポインタ `active_leaf_id` を保存します。これは、画面に表示中のスレッドの最後のメッセージを指します。スレッドは導出されます。アクティブなリーフから親ポインタをルートまでたどり、順序を逆にするだけです。編集や再試行は、同じ親の下に兄弟を 1 つ加えます。たどる途中で、自分と同じロールの兄弟を持つメッセージには、その中での位置が記録され、メッセージの下の矢印が読むのはそれだけです。

<CodeBlock
  code={`export function buildTimelineMessages(
    graph: ChatGraph,
    activeLeafId: string
  ): UIMessage[] {
    const path = getPathToLeaf(graph, activeLeafId)
    if (path.length === 0) return []
    return path.map((node) => {
      const siblings = (graph.childrenByParentId.get(node.parentId) ?? []).filter(
        (candidate) => candidate.role === node.role
      )
      const branchCount = siblings.length
      const branchIndex = Math.max(
        0,
        siblings.findIndex((candidate) => candidate.id === node.id)
      )
      return {
        id: node.id,
        role: node.role,
        parts: node.parts,
        metadata: {
          createdAt: node.createdAt,
          ...(branchCount > 1
            ? ({
                branchCount,
                branchIndex,
                isActiveBranch: true,
              } satisfies ChatBranchMetadata)
            : {}),
        },
      } satisfies UIMessage
    })
  }`}
  fileName="lib/chat-tree.ts"
  lang="ts"
/>

バージョンの切り替えはサーバー呼び出しで、次の兄弟を取り、最新の子をたどって葉まで降り、その葉をアクティブなものとして保存します。この設計のコストは、チャットを開くとそのチャットのすべてのメッセージ、つまり見ていないブランチまで読み込むことです。その代わり、メッセージはチャットと作成時刻のインデックスを使った 1 回のクエリで届き、木を扱うコードは、ブラウザとサーバーのどちらもインポートする素の TypeScript です。

### モデル ID からプロバイダーのクライアントへ

モデル ID には、`anthropic:claude-opus-4-6` のようにプロバイダーが含まれます。チャットのルートは、その ID をカタログと照合し、なければデフォルトのモデルに切り替えるので、ブラウザから Luma が載せていないモデルを要求することはできません。プレフィックスは 2 つを選びます。1 つはユーザーのキーで、そのリクエストの間だけ復号されます。もう 1 つはそのプロバイダーの AI SDK パッケージで、動的な `import()` で読み込まれるので、リクエストは必要な SDK だけを取り込みます。OpenAI 互換の API を持つプロバイダーは、独自のベース URL を指定して OpenAI のパッケージを使い回すので、新しく追加するのはカタログのエントリ 1 つで済みます。

### 保存時のキー

キーは、そのつど新しく生成したランダムな IV のもとで AES-256-GCM で暗号化され、IV、暗号文、認証タグの組として保存されます。GCM は暗号文を認証するので、データベース内で値が書き換えられても、別のキーに化けることはなく、復号に失敗します。これで守られるのは、データベースのダンプが流出したときのキーです。サーバーはプロバイダーを平文のキーで呼び出す必要があるため、保存しているすべてのキーを復号できます。データベースとマスターキーの両方を持つ人なら、誰でも同じことができます。

### モデルに送り返すもの

保存された返信には、画面に表示されるものがすべて残ります。推論、テキスト、ツール呼び出しとその結果です。次のリクエストと一緒に送る履歴は、サーバーで木から組み立て直され、その際に、先に 3 つのものが取り除かれます。

| 返信の一部               | 送り返す内容                     | 理由                                                                                                   |
| ------------------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 生成された画像           | テキスト `[image was generated]` | base64 のデータが、以降のすべてのリクエストに付いて回ってしまうため                                    |
| 推論                     | 何も送らない。画面上にだけ残る   | OpenAI の Responses API は、履歴から再送された推論のアイテムを拒否することがあるため                   |
| プロバイダーのメタデータ | 何も送らない                     | 特定のプロバイダーの過去のレスポンスを指すので、スレッドの途中でプロバイダーを切り替えられるようになる |

添付ファイルは非公開のバケットに置かれ、リクエストのたびに、10 分で期限が切れる新しいリンクが署名付きで発行されます。
