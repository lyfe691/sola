# 無料の映画とドラマ、そして一緒に観る場所

[Kinoa](https://kinoa.to) は、映画とドラマを無料で観られるサイトで、プレーヤーを中心にしたソーシャルな面もあります。プロフィール、フィード、コメント、メッセージ、そして一緒に観るためのルームです。始まりは検索ボックスとプレーヤーだけで、それ以外はすべて、リリースを重ねるごとに加わりました。

## 観るものを探す

すべては 1 つの検索ボックスから始まります。結果は入力している間に届き、それぞれにポスター、公開年、評価が付きます。もっとも有力なタイトルの残りの部分はグレーで補完され、矢印キーでリストの中を移動できます。ホームページでは、検索の下に、あなたが観ていた作品と、今週みんなが観ている作品が表示されます。

どのカードも、ホバーするとその場で開きます。ポスターが作品のアートワークへと広がり、あらすじと、観始めるためのボタンが現れます。

## 再生する

映画とドラマは、ほかのサイトから埋め込んだプレーヤーで再生されますが、どのプレーヤーにもすべての作品があるわけではありません。プレーヤーの下の行には、現在のサーバーの名前が表示され、各サーバーには「最高画質」「もっとも安定」のように、得意なことを示すタグが付きます。既定のものが読み込めないときは、ヒントが次のサーバーを提案し、タップ 1 回で切り替えられます。スマートフォンでは、再生をそのまま端末標準のフルスクリーンプレーヤーに切り替えることもできます。

ドラマにはシーズンごとのエピソード選択が付き、いま観ているエピソードがハイライトされます。

## 一緒に観る

ルームはリンクです。ホストが作品を選んでルームを共有すると、参加した全員が同じ瞬間を観て、プレーヤーの横にはチャットが付きます。ホストが一時停止したり、先へ飛ばしたり、エピソードを切り替えたりすると、ルーム全体がそれに従います。ルームの運営もホストが担います。

- **引き継ぎ。** ホストの役割は、ルームにいる誰にでも渡せます。ホストのタブが閉じられたときは、ルームがまだ残っている人に役割を渡します。
- **モデレーション。** ホストは、参加者を退出させ、再び入れないようにできます。
- **公開範囲。** ルームは、公開ディレクトリに載せることも、リンクを知っている人だけに限ることもできます。

## プロフィール、フィード、メッセージ

プレーヤーの周りには、小さなソーシャルネットワークがあります。

- **プロフィール。** どのアカウントにもハンドルと、kinoa.to/@name の公開ページがあり、お気に入り、ウォッチリスト、最近観た作品が載ります。スイッチ 1 つでプロフィール全体を非公開にできます。
- **フィード。** ユーザー同士がフォローし合い、作品に「いいね」やコメントをします。フィードには、Kinoa の全員のコメント、お気に入り、フォローが新しい順に並びます。
- **メッセージ。** ダイレクトメッセージには、リアクション、編集、削除、そしてブロックと報告の機能があります。
- **通知。** ベルのアイコンに、返信、メンション、いいね、フォローがそのつど集まり、フォローしている作品が公開されたときも知らせてくれます。

## デザインとモーション

Kinoa は、クリームとエスプレッソの温かみのある配色にキャラメル色のアクセントを添え、ライトとダークの 2 つのテーマを、選ばない限りシステムの設定に合わせて切り替えます。画面は小さく動いて、何が起きたのかを伝えます。

- ページはストリーミングで届き、各部分は、プレースホルダーがあった場所にそのまま現れます。
- サイドバーは滑らかに開閉します。
- 送信が拒否されたフォームでは、間違っている欄が揺れます。
- ダイアログは、いきなり切り替わらず、滑らかにサイズが変わります。

システムで動きを減らす設定にしている人には、これらの動きはすべて控えめになります。Kinoa はアプリとしてインストールすることもできます。パソコンや Android ではブラウザーから、iPhone では短いガイドに沿って行います。

## 実装

Kinoa は Next.js のアプリで、大部分がサーバーコンポーネントです。アカウント、データベース、そしてルームが動くリアルタイムチャンネルには Supabase を使っています。Vercel にデプロイしていて、next-intl で多言語化しています。

### ルームを 1 つの時計に合わせる

難しい制約は、埋め込みプレーヤーです。一時停止や指定時刻へのジャンプを、外から命じることができません。そこで、ホストからずれたゲストは、ホストの位置を、再読み込みにかかる時間の分だけ先に見積もった位置で、自分のプレーヤーを再読み込みします。再読み込みのたびに、実際に着地した位置を測って次の再読み込みを補正し、狙いはホストの 1 秒に満たない分だけ後ろに置きます。早いと場面のネタバレになり、遅いぶんには何も損なわれないからです。

<CodeBlock
  code={`/** Aim a touch behind the host — being early spoils, being late doesn't. */
  export const TARGET_DRIFT_SECONDS = -0.75
  /** Share of each landing error folded into the next lead estimate. */
  export const LEAD_LEARNING_RATE = 0.6
  export function anchorTargetFor(
    host: HostAnchor,
    now: number,
    leadSeconds: number
  ): AnchorTarget {
    if (!host.isPlaying) {
      return { time: Math.max(0, host.currentTime), play: false }
    }
    return {
      time: Math.max(0, projectPlayhead(host, host.at, now) + leadSeconds),
      play: true,
    }
  }
  export function nextLoadLead(lead: number, driftAtSettle: number): number {
    const error = driftAtSettle - TARGET_DRIFT_SECONDS
    const next = lead - error * LEAD_LEARNING_RATE
    return Math.min(
      MAX_LOAD_LEAD_SECONDS,
      Math.max(MIN_LOAD_LEAD_SECONDS, Number.isFinite(next) ? next : lead)
    )
  }`}
  fileName="lib/watch-together-playhead-sync.ts"
  lang="ts"
/>

再読み込みをすると、それまでのバッファを捨てることになります。そのためゲストが再読み込みするのは、数秒のずれが 2 回のチェックで続けて見つかったときだけで、何度か試してもだめなときは、判断を「Catch up」ボタンに委ねます。

### データベースが強制するルール

2 つのルールは、アプリではなくデータベースにあるため、どのクライアントに対しても守られます。

- **ルームを動かせるのはホストだけです。** ルームの制御チャンネルに対する行レベルセキュリティのポリシーです。結合テストでは、ゲストとしてサインインし、あらゆる制御コマンドを送って、ホスト側にどれも届かないことを確認しています。
- **ハンドルは 1 か所で確保します。** 長さや予約語からモデレーションまで、すべてのルールを 1 つのデータベース関数が持ち、2 人が同時に同じ名前を取ろうとしたときは、ユニークインデックスが決着をつけます。

### 通信の往復を減らす

コストのかかる処理が 3 つ、必要な回数よりはるかに多く実行されていました。

| 処理                                              | 変更前                                                              | 変更後                                                        |
| ------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------- |
| サインインしているユーザーの確認                  | 映画のページで Supabase Auth への呼び出しが 3 回、フィードでは 4 回 | レンダーごとに 1 回、すべてのヘルパーで共有                   |
| ウォッチリストの描画                              | 載っている作品ごとに TMDB へのリクエスト                            | データベースへの問い合わせ 1 回：各行がそのカードの情報を持つ |
| 開いているタブが 5 分ごとに行うバージョンチェック | 毎回サーバーレス関数                                                | Vercel のエッジキャッシュ                                     |

セッションの確認は、手元でのデコードではありません。ネットワークを越えて行われるので、レンダーごとに 1 回にしたことに意味がありました。

### 翻訳を漏れなく保つ

すべての文字列は、英語が元になっています。CI のチェックが、ほかのすべての言語ファイルを英語と突き合わせ、キーが足りなかったり余っていたりすると失敗します。そのため、新機能が翻訳が半分のままリリースされることはありません。
