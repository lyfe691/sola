# 無料の映画とドラマ、そして一緒に観る場所

## 観るものを探す

ホームページにあるのは、見出しが 1 つと検索バーだけで、バーの縁からは小さな白い生き物が顔をのぞかせています。結果は入力している間に届き、入力した文字で始まる最初のタイトルは、残りの部分がグレーで補完されます。生き物はキャレットの動きを追い、一致するものがないと困った顔をして、入力欄が空になると涙ぐみます。

どのページからでも検索パレットを開けます。パレットはサイドバーの検索欄から広がるように現れ、使い終わるとまたそこへ縮んで戻ります。検索をはじめ、いくつかの操作はキーボードでもできます。

| ショートカット            | 動作                                   |
| ------------------------- | -------------------------------------- |
| `Ctrl K`（Mac では `⌘K`） | どのページからでも検索パレットを開く   |
| `↑` と `↓`                | 結果の中を移動する                     |
| `Tab`                     | グレーの補完を確定する                 |
| `Enter`                   | ハイライトした結果を開く               |
| `Esc`                     | 検索を閉じる                           |
| `D`                       | ライトテーマとダークテーマを切り替える |
| `S`                       | サイドバーを表示または非表示にする     |

## 一緒に観る

ルームはリンクです。ホストが作品を選んでルームを共有すると、参加した全員が同じ瞬間を観て、プレーヤーの横にはチャットが付きます。ホストが一時停止したり、先へ飛ばしたり、エピソードを切り替えたりするとルーム全体がそれに従い、遅れたゲストには「Catch up」ボタンが表示されます。ルームの運営もホストが担います。

- **引き継ぎ。** ホストは、ルームにいる誰にでもホストの役割を渡せます。ホストが退出すると、役割はすぐに次の人に移ります。退出しないままホストのタブが閉じられたときは、2、3 分後に、まだルームに残っている人が引き継ぎます。
- **モデレーション。** ホストは参加者を退出させられます。ルームを始めた人は、自分がホストを務めている間なら、その人が再び入れないようにすることもできます。
- **公開範囲。** 公開ルームは「Watch Together」のページに一覧表示され、非公開のルームにはリンクからしか参加できません。

## プロフィール、フィード、メッセージ

プレーヤーの周りには、小さなソーシャルネットワークがあります。

- **プロフィール。** ハンドルを取得すると、アカウントに `kinoa.to/@name` のページができ、カバー画像、自己紹介、そしてアクティビティ、お気に入り、ウォッチリストのタブが付きます。スイッチ 1 つでタブを非公開にでき、その場合も名前、自己紹介、フォロワー数は表示されたままです。
- **コメント。** どの作品にもスレッド形式のコメントがあり、人気順か新着順で並べ替えられます。コメントにはネタバレの印を付けることもできます。
- **フィード。** Kinoa の全員の新しいコメントと、公開プロフィールのお気に入りとフォローが、新しい順に並びます。サインインしていると、サイドパネルに、ウォッチリストの作品の公開日と新しいエピソードも加わります。
- **メッセージ。** ダイレクトメッセージには、リアクション、編集、削除、そしてブロックと報告の機能があります。
- **通知。** ベルのアイコンに、返信、メンション、フォロー、メッセージがそのつど集まり、「Titles」タブには、ウォッチリストのうちこれから公開される作品が並びます。

## デザインとモーション

Kinoa の標準の見た目は、グレーの枠にはめ込んだ白いページで、ダークテーマではほぼ黒になります。青はフォーカスと選択の表示にだけ使っています。選ばない限りシステムのライト／ダークの設定に従い、「Settings」では、ほかのテーマを選んだり、色とコントラストを自分で設定したりできます。サイドバーでは、現在のページがコンテンツのパネルとつながったタブとして描かれ、別の行を選ぶと、タブがそこへ流れ込むように移ります。それ以外の動きは小さく、何が起きたのかを伝えます。

- メニューとポップオーバーは、それを開いた要素から広がるように現れ、メニューの背後のページはすりガラスのようにぼやけます。
- ダイアログは滑らかにサイズが変わり、ステップが進んでもボタンの位置は変わりません。
- ページはストリーミングで届き、各部分は、プレースホルダーがあった場所にそのまま現れます。
- 送信が拒否されたフォームでは、間違っている欄が揺れます。

システムで動きを減らす設定にしている人には、動きが控えめになります。Kinoa はアプリとしてインストールすることもできます。パソコンや Android ではブラウザーから、iPhone では短いガイドに沿って行います。

## 実装

Kinoa は Next.js のアプリで、大部分がサーバーコンポーネントです。アカウント、データベース、そしてルームが動くリアルタイムチャンネルには Supabase を使っています。Vercel にデプロイしていて、next-intl で多言語化しています。

### ルームを 1 つの時計に合わせる

難しい制約は、埋め込みプレーヤーです。一時停止や指定時刻へのジャンプを、外から命じることができません。そこで、ホストからずれたゲストは、ホストの位置を、再読み込みにかかる時間の分だけ先に見積もった位置で、自分のプレーヤーを再読み込みします。再読み込みのたびに、実際に着地した位置を測って次の再読み込みを補正し、狙いはホストより 1 秒に満たない分だけ後ろに置きます。早いと場面のネタバレになり、遅いぶんには何も損なわれないからです。

<CodeBlock
  code={`/** Aim a touch behind the host — being early spoils, being late doesn't. */
  export const TARGET_DRIFT_SECONDS = -0.75
  /** Share of each landing error folded into the next lead estimate. */
  export const LEAD_LEARNING_RATE = 0.6
  export function anchorTargetFor(
    host: HostAnchor,
    now: number,
    leadSeconds: number
  ): AnchorTarget {
    if (!host.isPlaying) {
      return { time: Math.max(0, host.currentTime), play: false }
    }
    return {
      time: Math.max(0, projectPlayhead(host, host.at, now) + leadSeconds),
      play: true,
    }
  }
  export function nextLoadLead(lead: number, driftAtSettle: number): number {
    const error = driftAtSettle - TARGET_DRIFT_SECONDS
    const next = lead - error * LEAD_LEARNING_RATE
    return Math.min(
      MAX_LOAD_LEAD_SECONDS,
      Math.max(MIN_LOAD_LEAD_SECONDS, Number.isFinite(next) ? next : lead)
    )
  }`}

再読み込みをすると、それまでのバッファを捨てることになります。そのためルームは、必要なときにしか再読み込みを求めません。

| 起きること                         | タイミング                                              |
| ---------------------------------- | ------------------------------------------------------- |
| ホストのプレーヤーが再生位置を送る | 5 秒ごと、および再生、一時停止、シークのたび            |
| 各ゲストがずれを測る               | 1 秒ごと                                                |
| 「Catch up」ボタンが表示される     | ホストとのずれが 4 秒を超えたとき                       |
| ゲストが自分で再読み込みする       | そのずれが 2 回続けて見つかったとき（間隔は最短 20 秒） |
| 自動の再読み込みをやめる           | 3 回再読み込みしても追いつけなかったとき                |

ルームでは VidFast だけを使います。この仕組みには、最後に止めた位置ではなく、指定した位置から再生を始めるプレーヤーが必要だからです。

### アニメのエピソードを放送日で対応づける

Kinoa では、リンクから視聴履歴、コメントまで、すべてが TMDB の ID で作品を識別しています。一方、アニメのプレーヤーが受け取るのは、アニメのデータベースである AniList の ID とエピソード番号です。また、2 つのカタログでは作品の区切り方が異なります。TMDB は Re:Zero の全 85 話を 1 つのシーズンにまとめていますが、AniList ではパートごとにエントリーが分かれています。

| AniList のエントリー | 話数 | TMDB のシーズン 1 | 放送    |
| -------------------- | ---- | ----------------- | ------- |
| シーズン 1           | 25   | 1–25              | 2016    |
| シーズン 2           | 13   | 26–38             | 2020    |
| シーズン 2 パート 2  | 12   | 39–50             | 2021    |
| シーズン 3           | 16   | 51–66             | 2024–25 |
| シーズン 4           | 19   | 67–85             | 2026    |

そこで Kinoa は、TMDB の ID に対応する AniList のエントリーを調べ、次に各エントリーの放送日を調べて、前後 1 日の幅で日付の合うエピソード同士を対応づけます。

日付が合わないエピソードを対応づけるのは、確定した対応のすぐ隣にあって、その部分で対応のついていないエピソードの数が両方のカタログで同じときだけです。それ以外は対応づけないまま、通常のサーバーで再生します。対応を間違えると違うエピソードが再生されますが、対応がなければサーバーが変わるだけだからです。私が確かめた人気の 30 作品では、この方法でエピソードの 99〜100% が対応づけられました。

### データベースが強制するルール

3 つのルールは、アプリではなくデータベースにあるため、どのクライアントに対しても守られます。

- **ルームを動かせるのはホストだけです。** ルームの制御チャンネルに対する行レベルセキュリティのポリシーです。結合テストでは、ゲストとしてサインインし、キックや同期といったホスト用のコマンドを送って、ホスト側にどれも届かないことを確認しています。
- **退出させたゲストは、すぐに切り離されます。** Supabase Realtime は、クライアントが参加する時点でプライベートチャンネルのポリシーを確認しますが、そこから特定のユーザー 1 人だけを外す呼び出しはありません。そこで、各ルームのチャンネル名には、キックや入室禁止のたびに変わるキーを含めています。ほかの全員は新しいキーで参加し直し、退出させられたクライアントは、何も書き込まれないチャンネルに取り残されます。
- **ハンドルは 1 か所で確保します。** 長さや予約語から、モデレーション、変更の間に置く 30 日の待機期間まで、すべてのルールを 1 つのデータベース関数が持ち、2 人が同時に同じ名前を取ろうとしたときは、ユニークインデックスが決着をつけます。

### 通信の往復を減らす

コストのかかる処理が 3 つ、必要な回数よりはるかに多く実行されていました。

| 処理                                              | 変更前                                                              | 変更後                                                      |
| ------------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------- |
| サインインしているユーザーの確認                  | 映画のページで Supabase Auth への呼び出しが 3 回、フィードでは 4 回 | レンダーごとに 1 回、すべてのヘルパーで共有                 |
| ウォッチリストの描画                              | 載っている作品ごとに TMDB へのリクエスト                            | 1 ページにつき問い合わせ 1 回：各行がそのカードの情報を持つ |
| 開いているタブが 5 分ごとに行うバージョンチェック | 毎回サーバーレス関数                                                | Vercel のエッジキャッシュ                                   |

セッションの確認は、手元でのデコードではありません。ネットワークを越えて行われるので、レンダーごとに 1 回にしたことに意味がありました。

### 翻訳を漏れなく保つ

すべての文字列は、英語が元になっています。CI のチェック（`pnpm check:i18n`）が、ほかのすべての言語ファイルのキーを英語と突き合わせ、キーが足りなかったり余っていたりすると失敗します。
