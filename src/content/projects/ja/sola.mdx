## ホームページ

ホームページは、あいさつと、次へ進むための入口でできています。あいさつの中の名前は、私が名乗っている Yanis、Sebi、lyfe691 を順番に巡り、押すと次の名前に移ります。その下の行も入れ替わり、それぞれの文がぼやけた状態から一文字ずつ綴られます。あいさつの上には小さなリンクがあり、いま取り組んでいることを指しています。

2 つのボタンはガラス調で、縁には柔らかな光のふちどりと、ボタンの周りを巡りながらポインターの方を向くきらめきがあります。下のソーシャルリンクは、ホバーすると開いて、名前とブランドカラーが現れます。別のページへ移るときは、いまのページがぼやけて消え、次のページが同じぼかしからピントを結びます。初めて訪れたときは、メニューのそばに案内が表示され、私が選んだテーマと背景、そしてそれらを変えられる場所を伝えます。

## テーマと背景

右上のメニューで、サイト全体の見た目を変えられます。ライト、ダーク、システムに合わせる設定のほかに、独自のパレットを持つカスタムテーマがあり、ホバーすると、選ぶ前に小さなプレビューが表示されます。新しいテーマは 0.5 秒足らずで古いテーマの上に溶け込むように現れ、メニューは開いたままなので、次のテーマもクリックひとつで選べます。

どのページの背後でも、アニメーションする背景を動かせます。テーマから色を受け継ぐ WebGL のシーンで、同じメニューから選びます。柔らかなグラデーションのものもあれば、シルクや水彩のように動くものもあり、ポインターを追う流体もひとつあります。

## プロジェクト

プロジェクトのページは、カードを並べたグリッドです。各カードには、そのプロジェクト固有の色のカバー、角の切り欠きにはめ込まれた日付、短い説明、使っている技術が載っています。フィルターで個人のプロジェクトとクライアント向けの仕事を分け、メニューで「おすすめ」「新しい順」「古い順」「名前順」に並べ替えられます。

順序が変わると、画面上のすべてのカードが、短いぼかしを伴ってクロスフェードし、その位置に入るカードへ入れ替わります。そのため、中身が変わってもグリッドの形は保たれます。

## 実装

Sola は TypeScript で書かれた React アプリで、Vite でビルドし、Tailwind CSS と shadcn/ui のコンポーネントでスタイリングし、Motion でアニメーションさせています。背景は three.js と OGL で描いています。Vercel にデプロイしていて、サーバーレス関数が GitHub のアクティビティと Changelog のコミットを取得します。

### 表示が始まった時点で、コンテンツは描画済みとして数えられる

このサイトの登場アニメーションはすべてフェードで、以前はどれも不透明度 0 から始まっていました。Chrome の Largest Contentful Paint（LCP）は、画面上で最大のコンテンツが描画されたとみなす時点ですが、不透明度 0 で描画されたものは対象から外れ、しかもフェードはコンポジターで動くので、再描画は行われません。そのため、ブロックはフェードが終わって初めて数えられ、どのページの LCP にも 0.7 秒分のなめらかな動きがそのまま加わっていました。CPU を 4 倍遅くした Chrome のトレースでは、お問い合わせページのサブタイトルは 941 ms で表示を始め、1536 ms で数えられました。

登場アニメーションは現在 0.001 から始まります。これは白の上でも、8 ビットの色チャンネルの 1 段階に満たない値です。見た目は何も変わりませんが、ブラウザはフェードが始まった時点で描画を数えます。同じトレースでの結果です。

| ページ       | 最大の描画が数えられた時点、変更前 | 変更後  |
| ------------ | ---------------------------------- | ------- |
| お問い合わせ | 1536 ms                            | 804 ms  |
| プロジェクト | 2764 ms                            | 1136 ms |
| ホーム       | 2032 ms                            | 1120 ms |

### ルートの一覧はひとつだけ

すべてのページは `src/config/routes.ts` の 1 つのエントリで、パス、読み込むコード、レイアウト、タブのタイトルを持ちます。

<CodeBlock
  code={`{
    path: "/projects",
    layout: "app",
    ...page(() => import("@/pages/Projects")),
    title: (t) => t.projects.title,
  },`}
  fileName="src/config/routes.ts"
  lang="ts"
/>

ルーターはこの一覧から描画され、`index.html` に小さなスクリプトを書き込むビルドステップも同じ一覧を使います。スクリプトはアドレスを同じ一覧と照合し、メインバンドルがまだ届いている途中で、そのページのコードのダウンロードを始めます。以前は、バンドル全体のダウンロードと実行が終わってから、ようやくページのコードを要求していました。エントリのパスとページの組み合わせが崩れるとビルドは失敗するので、一覧とスクリプトがずれることはありません。

### 訪問者ごとに 1 つの言語

以前は、訪問者が読むのは 1 言語だけなのに、すべての翻訳が起動時のバンドル（minify 後で 156 KB）に含まれていました。英語はフォールバックとして引き続きバンドルされ、ほかの言語はそれぞれ圧縮後で約 11 KB の独立したチャンクになり、最初のレンダリングの前にページのコードと一緒に取得されます。そのため、ドイツ語での訪問も英語での訪問より待たされることはありません。言語を切り替えたときは、新しい言葉が読み込まれるまで、いまの言葉が画面に残ります。
