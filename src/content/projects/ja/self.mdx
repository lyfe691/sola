# Windows PowerShell 向けの Neofetch 風システム情報表示

Self は、Linux の [Neofetch](https://github.com/dylanaraps/neofetch) と同じように、Windows PowerShell で画像とシステム情報の列を並べて表示します。画像は好きな画像ファイルでよく、色付きの文字でターミナル上に描き直されます。システム情報は、Windows のエディションからディスクまで、多岐にわたります。

## 表示される内容

左には、`images` フォルダの画像か `--image` で渡した任意のファイルが、文字数で指定した高さと幅に縮小されて表示されます。1 つの文字セルにはピクセルが 2 つ入り、どのピクセルも 24 ビットのエスケープコードで自分の色を保つので、写真や絵は、幅が数十文字でも見分けがつきます。点字モードでは、代わりにより細かい点で描き、色はセルごとに 1 色です。

右の `user@host` の下には、Windows のエディション、稼働時間、Chocolatey、Scoop、winget のパッケージ数、シェル、画面の解像度とテーマ、プロセッサ、グラフィックスカード、メモリ、ディスクが並びます。どの行を表示するかは設定で決まり、ラベルの色はカラーテーマで決まります。列の最後には、情報の収集にかかった時間と、昔ながらのコンソールの 16 色の列が並びます。

## ASCII アート

## インストールとセットアップ

Self は PowerShell の 1 行でインストールできます。

```powershell
iwr -Uri "https://raw.githubusercontent.com/lyfe691/self/main/install.ps1" -UseBasicParsing | iex
```

スクリプトは、Self をユーザープロファイル内の `self` フォルダにダウンロードし、ランチャーの `self.bat` を追加し、そのフォルダをユーザーの `PATH` に加え、Python のパッケージを pip でインストールします。必要なのは Python で、管理者権限は不要です。そのあとは、`self` は他のコマンドと同じように使えます。

| コマンド              | 動作                                                                               |
| --------------------- | ---------------------------------------------------------------------------------- |
| `self`                | 画像とシステム情報を表示します                                                     |
| `self --setup`        | 表示の種類、画像または絵、テーマ、サイズを尋ね、`config.json` に保存します         |
| `self --image <file>` | 別の画像を使います。`images` フォルダの画像でも、任意のパスでも構いません          |
| `self --ascii <name>` | 画像の代わりに、`ascii` フォルダの絵を使います                                     |
| `self --no-cache`     | 5 分間のキャッシュではなく、情報を新しく収集します                                 |
| `self --update`       | 最新バージョンを取得します。設定、キャッシュ、自分で追加した画像には手を付けません |

## 実装

Self は、表示、画像、システム情報、カラーテーマの 4 つのモジュールからなる、小さな Python プログラムです。画像の読み込みとリサイズは Pillow、メモリ、ディスク、稼働時間の取得は psutil、テーマの色は colorama が担います。

### 1 文字に 2 ピクセル

ターミナルのセルは、高さが幅の約 2 倍あります。半ブロック文字 `▀` は、セルの上半分を前景色で塗り、下半分を背景色に任せるので、両方を設定したセルには、ほぼ正方形のピクセルが 2 つ入ります。`rgb_to_ansi` が、前景用の `\033[38;2;r;g;bm` と背景用の `\033[48;2;r;g;bm` の 2 つのエスケープコードを組み立て、ブロックモードは画像を 2 行ずつたどります。

<CodeBlock
  code={`for y in range(0, img_height, 2):
      line = ""
      for x in range(img_width):
          r_upper, g_upper, b_upper = pixels[x, y]
          if y + 1 < img_height:
              r_lower, g_lower, b_lower = pixels[x, y + 1]
          else:
              r_lower, g_lower, b_lower = r_upper, g_upper, b_upper
          # '▀' character (upper half block)
          line += f"{rgb_to_ansi(r_upper, g_upper, b_upper)}{rgb_to_ansi(r_lower, g_lower, b_lower, bg=True)}▀{RESET}"
      lines.append(line)`}
  fileName="image_handler.py"
  lang="python"
/>

高さと幅が等しいとき、ブロックモードは幅を 2 倍にします。正方形の画像には、行の 2 倍の列が必要だからです。冒頭のクリップの 26 × 26 という設定は、52 × 52 ピクセルの画像になり、Pillow が最近傍法でリサイズして、52 文字の行 26 本として出力されます。

### 見える幅でそろえる

これらの行は長くなります。どのセルにも、前景色のコード、背景色のコード、文字、リセットが付くので、その画像の 1 行は、見える 52 列に対して約 1900 文字にもなり、`len()` はそのすべてを数えます。画像の隣にシステム情報をそろえるため、Self は、正規表現でエスケープコードを取り除いたあとの各行の幅を測り、短い行を空白で最も長い行の幅まで埋めます。

### 点字 1 文字に 8 つの点

点字モードは、色と引き換えに解像度を得ます。Unicode の点字ブロックは U+2800 から始まり、セルの 8 つの点を、オフセットのビットとして符号化するので、2 × 4 の格子上のどんなパターンも 1 文字になります。番号の付け方は歴史的な経緯によるものです。点 1 から 3 は左の列を上から下へ、点 4 から 6 は右の列を上から下へ並び、点 7 と 8 は、あとから 8 点点字のために加えられたので、最下段はビット 6 と 7 になります。ピクセルの位置からビットへの対応は次のとおりです。

<CodeBlock
  code={`bit_position_map = {
      (0, 0): 0, (1, 0): 3,
      (0, 1): 1, (1, 1): 4,
      (0, 2): 2, (1, 2): 5,
      (0, 3): 6, (1, 3): 7
  }`}
  fileName="image_handler.py"
  lang="python"
/>

画像はグレースケールに変換され、ピクセルが 127 より暗いところに点が立ち、セル全体は 8 つのピクセルの平均色になります。2 つのモードを並べると、同じものを引き換えにしているのがわかります。

| モード   | 1 文字あたりのピクセル数       | 色                                      |
| -------- | ------------------------------ | --------------------------------------- |
| ブロック | 2 つ、上下に 1 つずつ          | どのピクセルも自分の色を保つ            |
| 点字     | 8 つ、2 × 4 の格子上の点として | セルごとに 1 色で、点ごとにオンかオフか |

暗いターミナルでは、点字の点が画像の暗い部分をなぞるため、色の大半が失われます。README がブロックモードを勧めているのは、そのためです。

### 情報を 5 分間キャッシュする

稼働時間、メモリ、ディスクは、psutil が直接答えます。ほかの行の大半は、短い PowerShell コマンドから得ます。Windows のエディション、レジストリから読むテーマ、パッケージ数などです。各問い合わせは、それぞれ専用の `powershell.exe` を、2 秒のタイムアウトを付けて起動するので、遅い応答が 1 つあっても残りを待たせることはなく、`-NoProfile` を付けるので、ユーザーのプロファイルスクリプトが毎回実行されることもありません。時間のかかる 10 個の問い合わせは、スレッドプールで並列に実行されます。

結果は `cache/sysinfo.json` に 5 分間保存され、`--no-cache` を付けるとそれを使いません。「Executed in」の行は、この手順の所要時間を測ったものです。私のマシンでは、新しく収集すると約 1 秒、キャッシュから読むと 0.00 秒かかります。描画した画像も 1 日キャッシュされ、キーはファイルのパスと更新日時、サイズ、モードです。
