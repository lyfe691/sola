# Un chat de IA multiproveedor que funciona con tus propias claves de API

[Luma](https://luma.ysz.life) es una aplicación de chat para quienes ya pagan por el acceso a la API de uno o varios proveedores de modelos. Añades tus claves una sola vez, eliges un modelo para cada chat y cada solicitud va a ese proveedor con tu clave.

## Elegir un modelo

El botón de modelo del cuadro de mensaje abre un selector con todos los modelos que ofrece Luma, agrupados por proveedor. Una columna de logotipos de proveedores salta de un grupo a otro, el cuadro de búsqueda filtra mientras escribes y unos iconos pequeños indican qué admite cada modelo: razonamiento, imágenes como entrada, uso de herramientas y PDF. Una estrella añade un modelo a la lista de favoritos de la columna.

Cada chat conserva su propio modelo, así que una conversación puede funcionar con Claude y la siguiente con GPT-5 Mini. Los modelos cuyo proveedor aún no tiene clave llevan un candado, y al elegir uno aparece encima del cuadro de mensaje un aviso que nombra la clave que falta, con un botón que abre los ajustes.

## Preguntar

El cuadro de mensaje admite texto, imágenes y archivos como PDF, CSV y Markdown, que puedes pegar, soltar encima o elegir en el menú del signo más. Ese mismo menú fija un modo para el siguiente mensaje:

- **Create image** pide al modelo que responda con una imagen.
- **Web search** hace que busque información y cite sus fuentes.
- **Study and learn** pide una enseñanza estructurada con ejemplos resueltos.

## Respuestas

Las respuestas se escriben en pantalla a medida que llegan, en Markdown. Los bloques de código aparecen resaltados y llevan botones para copiar y descargar, y las fórmulas matemáticas y los diagramas se muestran en el propio texto. Cuando un modelo razona antes de responder, el razonamiento se pliega en una fila «Thought for N seconds» encima de la respuesta, y los modelos de Claude tienen pensamiento extendido sin que haya que activar nada. Las respuestas de una búsqueda web llevan sus fuentes como pequeños chips junto a las frases que las usan.

## Editar, reintentar y encontrar chats

Nada de lo que hay en una conversación se sobrescribe. Al editar un mensaje que enviaste se añade una versión nueva junto a la anterior, con una respuesta nueva debajo, y unas flechas bajo el mensaje permiten pasar de una versión a otra. Reintentar una respuesta hace lo mismo en el lado de la respuesta, y el menú de reintento puede enviar la pregunta a otro modelo, de modo que las respuestas de dos modelos al mismo mensaje quedan a una flecha de distancia.

Los chats nuevos reciben su título de un modelo pequeño y barato, con una de tus claves. La barra lateral los enumera con los fijados primero, y desde allí cada uno se puede fijar, renombrar o eliminar. Los ajustes pueden exportar todos tus chats como descarga o eliminarlos. Las acciones habituales tienen atajos, con Ctrl en Windows y ⌘ en un Mac:

| Atajo                | Hace                                          |
| -------------------- | --------------------------------------------- |
| Ctrl K               | Busca en todos los chats, agrupados por fecha |
| Ctrl Shift O         | Inicia un chat nuevo                          |
| Ctrl M               | Abre el selector de modelos                   |
| Ctrl U               | Adjunta un archivo                            |
| Ctrl Shift S         | Muestra u oculta la barra lateral             |
| Shift Esc            | Salta al cuadro de mensaje                    |
| Ctrl Shift Backspace | Elimina el chat abierto                       |

## Tus claves de API

Los ajustes tienen una fila por proveedor, cada una con un enlace a la página donde se obtiene una clave. Luma prueba una clave nueva con el proveedor antes de guardarla, así que una clave que el proveedor rechaza se descarta al instante. Las claves se cifran antes de almacenarse, y el navegador solo llega a saber qué proveedores tienen una.

## Cómo está hecho

Luma es una aplicación de Next.js 16 sobre React 19. El Vercel AI SDK transmite las respuestas y llega a cada proveedor a través del paquete propio de ese proveedor, Supabase guarda las cuentas, los chats y los archivos subidos, y los trazos de la pantalla de inicio son un shader de Three.js.

### Las conversaciones son árboles

Cada mensaje es una fila con un `parent_id`, y un chat guarda un puntero más, `active_leaf_id`, al último mensaje del hilo que se ve en pantalla. El hilo se deriva: se parte de la hoja activa, se siguen los punteros al padre hasta la raíz y se invierte el orden. Una edición o un reintento añade un hermano bajo el mismo padre, y el recorrido marca cada mensaje que tiene hermanos de su mismo rol con su lugar entre ellos, que es todo lo que leen las flechas bajo un mensaje.

    graph: ChatGraph,
    activeLeafId: string
  ): UIMessage[] {

    if (path.length === 0) return []
    return path.map((node) => {
      const siblings = (graph.childrenByParentId.get(node.parentId) ?? []).filter(
        (candidate) => candidate.role === node.role
      )
      const branchCount = siblings.length
      const branchIndex = Math.max(
        0,
        siblings.findIndex((candidate) => candidate.id === node.id)
      )
      return {
        id: node.id,
        role: node.role,
        parts: node.parts,
        metadata: {
          createdAt: node.createdAt,
          ...(branchCount > 1
            ? ({
                branchCount,
                branchIndex,
                isActiveBranch: true,
              } satisfies ChatBranchMetadata)
            : {}),
        },
      } satisfies UIMessage
    })
  }`}

Cambiar de versión es una llamada al servidor que toma el siguiente hermano, baja por el hijo más reciente hasta una hoja y guarda esa hoja como la activa. El coste de este diseño es que abrir un chat lee todos sus mensajes, incluidas las ramas que no estás mirando. A cambio, llegan en una sola consulta sobre un índice de chat y fecha de creación, y el código del árbol es TypeScript sin más, que importan tanto el navegador como el servidor.

### De un id de modelo a un cliente de proveedor

Los ids de modelo llevan su proveedor, como en `anthropic:claude-opus-4-6`. La ruta del chat comprueba el id con el catálogo y recurre al modelo por defecto cuando no está, así que el navegador no puede pedir un modelo que Luma no lista. El prefijo selecciona la clave del usuario, que se descifra solo para esa solicitud, y el paquete del AI SDK del proveedor, que se carga con un `import()` dinámico para que cada solicitud solo cargue el SDK que necesita. Los proveedores con una API compatible con OpenAI reutilizan el paquete de OpenAI con su propia URL base, así que añadir uno es una entrada del catálogo.

### Claves en reposo

Una clave se cifra con AES-256-GCM bajo un IV aleatorio nuevo y se guarda como IV, texto cifrado y etiqueta de autenticación. Como GCM autentica el texto cifrado, un valor modificado en la base de datos no se puede descifrar en lugar de convertirse en una clave distinta. Esto protege las claves en un volcado filtrado de la base de datos. El servidor tiene que llamar a los proveedores con la clave en texto plano, así que puede descifrar todas las claves que guarda, y también puede hacerlo cualquiera que tenga a la vez la base de datos y la clave maestra.

### Qué vuelve al modelo

Una respuesta guardada conserva todo lo que muestra la pantalla: razonamiento, texto, llamadas a herramientas y sus resultados. El historial que se envía con la siguiente solicitud se reconstruye desde el árbol en el servidor, y antes se le quitan tres cosas:

| Parte de la respuesta   | Se devuelve como                 | Por qué                                                                                                            |
| ----------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Una imagen generada     | El texto `[image was generated]` | Si no, el base64 viajaría con cada solicitud posterior                                                             |
| Razonamiento            | Nada, solo se queda en pantalla  | La Responses API de OpenAI puede rechazar elementos de razonamiento reenviados desde el historial                  |
| Metadatos del proveedor | Nada                             | Apuntan a respuestas anteriores de un solo proveedor, así que un hilo puede cambiar de proveedor a mitad de camino |

Los adjuntos se quedan en un bucket privado, y cada solicitud firma enlaces nuevos hacia ellos que caducan a los diez minutos.
