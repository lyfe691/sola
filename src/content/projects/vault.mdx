# An identity stack you can tear down and rebuild

Vault is a local OIDC sandbox. OIDC — OpenID Connect, the identity layer sitting on top of OAuth 2.0 — is easy to read about and hard to hold onto until you have stood one up yourself, so I built one: Keycloak 26 as the provider, PostgreSQL behind it, a FastAPI service that verifies the tokens, and a Next.js frontend with a sign-in page and two role-gated dashboards.

## Why the realm is a Terraform file

Keycloak's admin console will let you click together a realm, a client, two roles and a user in about ten minutes. The problem starts on the second run: something is configured differently, there is no diff to read, and the console holds no record of how you got there. A sandbox you can't reset is not a sandbox.

So the identity configuration lives in `terraform/main.tf` and nowhere else. The realm, both realm roles, the demo user, the role assignment and the confidential client are declared resources.

<CodeBlock
  code={`resource "keycloak_realm" "vault" {
  realm        = "vault-core"
  enabled      = true
  display_name = "Vault Core Realm"
}
resource "keycloak_role" "admin_role" {
  realm_id    = keycloak_realm.vault.id
  name        = "admin"
  description = "Administrator role"
}
resource "keycloak_user_roles" "demo_user_roles" {
  realm_id = keycloak_realm.vault.id
  user_id  = keycloak_user.example_user.id
  role_ids = [
    keycloak_role.admin_role.id,
    keycloak_role.user_role.id,
  ]
}`}
  fileName="terraform/main.tf"
  lang="hcl"
/>

## What the backend actually checks

`app/backend/main.py` fetches the realm's discovery document at `/.well-known/openid-configuration`, reads `jwks_uri` out of it, and verifies every incoming RS256 token against that key set with both the issuer and the audience pinned. The token may arrive as an `Authorization: Bearer` header or as an `access_token` cookie; either path lands in the same verifier.

Authorization is a second, separate step. A `require_roles` dependency reads `realm_access.roles` from the decoded payload and answers 403 naming the roles it wanted. `/admin` requires `admin`, `/user` requires `user`, and `/me` requires only a valid token.

## What it was for

Twenty-five commits over three days in May 2025 bought one durable idea: identity configuration belongs in a file, not in the state of an admin console.
